Update the role dropdown selection behavior so that it automatically selects the correct UI role based on the logged-in user role.
⚠️ Important
Do NOT change existing role logic
Do NOT remove the dropdown
Do NOT modify permission logic
Only update how the dropdown selected value is set
The dropdown should simply reflect the detected role, not control it.
Objective
When a user logs in, the application already determines the active UI role using:
userType
+
userProfile.role
The role dropdown must automatically select the matching role.
The dropdown should always prioritize the logged-in user's role.
Manual dropdown selection should not override the logged-in role.
Source of Data
The role should be determined using the following priority:
localStorage.userType
localStorage.userProfile.role
If these keys are not available:
fallback → currentUser.role
Role Mapping
Map the logged-in role to the existing UI dropdown role.
Logged User Role	userType	Dropdown UI Role
Sail Admin	Office	Sail Admin
Super Admin	Office	Client Admin
Vessel Admin	Ship	Head Of Dept
Vessel User	Ship	Vessel
Behavior
Detect the logged-in user role.
Map it to the UI role used by the dropdown.
Set the dropdown value programmatically.
Example flow:
Detect userType
↓
Detect userProfile.role
↓
Map role to UI role
↓
Set dropdown selected value
Example Logic
let selectedRole;
if (userType === "Office") {
   if (userProfile.role === "Sail Admin") {
      selectedRole = "Sail Admin";
   }
   else if (userProfile.role === "Super Admin") {
      selectedRole = "Client Admin";
   }
}
if (userType === "Ship") {
   if (userProfile.role === "Vessel Admin") {
      selectedRole = "Head Of Dept";
   }
   else if (userProfile.role === "Vessel User") {
      selectedRole = "Vessel";
   }
}
Then update the dropdown:
setRole(selectedRole)
or assign it to the dropdown control value.
Final Expected Result
When the application loads:
The correct role UI is already active
The dropdown automatically shows that role as selected
The dropdown is only a visual indicator
The logged-in role always takes priority
Example:
Logged user:
userType = Office
role = Sail Admin
Result:
UI Role → Sail Admin
Dropdown → Sail Admin (selected)
The dropdown must always reflect the detected role automatically.
