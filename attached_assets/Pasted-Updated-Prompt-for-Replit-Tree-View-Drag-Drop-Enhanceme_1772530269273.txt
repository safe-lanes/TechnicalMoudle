Updated Prompt for Replit – Tree View Drag & Drop Enhancement (Component Section)

Objective

Enhance the Tree View Edit (Drag & Drop) functionality in the Component Section to allow flexible repositioning of components within the hierarchy, with persistent sort order.

1. Drag & Drop Functionality

The user must be able to drag any component and drop it:

Below any other component in the tree view.

The dragged component should be positioned immediately below the selected target component.

2. Hierarchy Handling

When a component is dragged and dropped:

If dropped below a component at the same level:

It should reorder within that hierarchy level.

If dropped below a component at a different level:

The dragged component should become a child of the target component (if hierarchy rules allow).

The system must update:

parent_component_code

sort_order

3. Save & Persistence Requirement (Mandatory)

After drag and drop, when the user clicks Save:

The updated hierarchy and sort order must be stored permanently in the database.

On next load of the Component section:

The tree must render strictly based on the saved parent_component_code and sort_order.

The updated order must persist exactly as last saved.

No temporary or session-based sorting logic is allowed.

4. UI Behavior

Show a clear visual indicator while dragging:

Highlight the target component.

Show insertion position (below).

After successful save:

Reflect the updated structure immediately.

No full page reload required.

Maintain expand/collapse state where possible.

5. Backend Logic Requirements

Update hierarchy fields properly:

parent_component_code

sort_order

Ensure:

No circular hierarchy (component cannot become child of its own descendant).

Referential integrity is maintained.

Changes are committed atomically (transaction-safe).

6. Validation Rules

Prevent invalid hierarchy moves.

Show proper validation error if move is not permitted.

Ensure consistent behavior with Fleet Component logic if shared.

7. Expected Behavior

User drags a component.

Drops it below any target component.

Clicks Save.

Structure is stored permanently.

On next page load, the tree appears in the exact saved order.

No unintended reshuffling occurs.
