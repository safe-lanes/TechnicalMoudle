Raplit Prompt — Copy Vessel (Spares) Validation Enhancement
Module

PMS → Fleet & Vessel Manager → Copy Vessel → Spares

🎯 Objective

Enhance the existing Copy Vessel – Spares functionality by introducing field-level exclusions during replication.

Current functionality correctly copies vessel spare configuration from Source Vessel to Target Vessel.

Now implement validation to prevent copying stock and storage-location related data.

📌 Change Type

Backend Validation Adjustment

No UI change
No workflow change
No permission change

⚙️ Updated Copy Logic Requirement

When copying spares from:

Source Vessel → Target Vessel


The system must:

Replicate spare master linkage

Replicate spare-to-component mapping

Replicate configuration attributes

Exclude stock balance and physical storage data

🚫 Columns That Must NOT Be Copied

The following fields from the spares table must be excluded during replication:

robLocationA
robLocationB
location
location2

🔎 Expected Behavior for Excluded Fields

For the Target Vessel:

These fields must be:

Set to 0 (for ROB fields)
OR

Set to NULL / default (for location fields)

They must NOT inherit values from the Source Vessel.

🧠 Rationale

These fields represent:

Remaining On Board (ROB) stock quantities

Physical storage location identifiers

Stock levels and physical storage positions are vessel-specific and must not be transferred between vessels.

Copying them would:

Create incorrect opening balances

Distort inventory valuation

Corrupt vessel-level stock tracking

🧩 Data Integrity Rules

Do not copy inventory balances

Do not copy physical storage allocation

Maintain spare master references

Preserve component-spare linkage

Do not affect inventory transaction history

🧪 Validation Checklist

After copy:

Spare master mapping must replicate correctly

ROB values must initialize to 0

Location fields must be empty/default

No inherited stock quantity should appear

No impact on inventory ledger

📌 Scope Limitation

Applies only to:

Copy Vessel → Spares


No impact on:

Components copy logic

Jobs copy logic

Inventory transaction engine

Consumption reports

Bulk update functionality

✅ Expected Outcome

Clean spare configuration replication

No stock contamination between vessels

Accurate vessel-level inventory initialization

Preserved data integrity
