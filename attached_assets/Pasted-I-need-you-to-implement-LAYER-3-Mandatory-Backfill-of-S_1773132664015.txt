BACKGROUND / PROBLEM STATEMENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Currently, when a work order is completed late (missed_cycles >= 1), 
the system detects and counts the skipped cycles (Layer 1) and 
corrects the future schedule (Layer 2). However, the HISTORY is still 
clean — there is no permanent record of the specific cycles that were 
missed. The audit trail has a gap.

EXAMPLE:
- Job frequency: 1 Week
- WO due: 01-Jan-2026
- Crew completes on 22-Jan-2026 (3 weeks late, missed_cycles = 3)
- Layer 1 flags: 3 cycles skipped
- Layer 2 corrects next due to: 08-Jan-2026

BUT there is no record for what happened on 08-Jan-2026, 15-Jan-2026, 
and 22-Jan-2026. Those missed cycles are invisible in the maintenance 
history. A superintendent reviewing the records cannot see the GAPS.

THE FIX — BACKFILL:
When a work order is completed with missed_cycles >= 1, the system 
must automatically create a separate historical record for EACH 
missed cycle. These records must:
1. Be permanently stored and CANNOT be deleted
2. Have a clear status of "NOT PERFORMED" or "SKIPPED"
3. Show exactly which scheduled date was missed
4. Be visible in the A4 Work History table on the Work Order Form
5. Be visible in the maintenance history / component history

"Skipped WO Record" = A record in the component_maintenance_history 
table that represents a maintenance cycle that was NOT performed. 
It is NOT a real work order — it is only a history record.
It has:
  - status = 'SKIPPED'
  - workDescription = 'Job not performed — cycle missed'
  - dateCompleted = the date the cycle WAS DUE (not the actual

  - originalDueDate = that specific cycle's scheduled date
  - performedBy = null (nobody performed it)
  - A reference back to the parent completed work order that detected it
    (so we know WHY this SKIPPED record was created)

STEP 2 — CREATE A createSkippedCycleRecords() UTILITY FUNCTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

server/modules/work-orders/services/workOrderCompletionService.ts 
or create a new file 
server/modules/work-orders/utils/skippedCycleBackfill.ts

Function signature:
  async function createSkippedCycleRecords(
    workOrderId: string,      — ID of the completed work order
    jobId: string,            — ID of the job template
    componentId: string,      — ID of the component
    vesselId: string,         — ID of the vessel
    originalDueDate: string,  — the original scheduled due date of the 
                                completed WO (from Layer 2)
    missedCycles: number,     — number of cycles missed (from Layer 1)
    frequencyValue: number,   — job frequency value (e.g., 1)
    frequencyUnit: string,    — job frequency unit (e.g., "Weeks")
    db: DrizzleDB             — the database instance
  ): Promise<void>

Function logic — do the following inside this function:

1. Validate inputs:
   - If missedCycles <= 0, return immediately (nothing to backfill)
   - If originalDueDate is null/invalid, log a warning and return

2. Calculate the dates of each skipped cycle:
   Use date-fns add() function with the frequency interval.
   
   The skipped cycles are the cycles that should have happened 
   BETWEEN the originalDueDate and the completion date.
   
   Formula:
     skippedDates = []
     for i = 1 to missedCycles:
       skippedDate = add(originalDueDate, { 
         [frequencyUnit]: frequencyValue * i 
       })
       skippedDates.push(skippedDate)
   
   Example:
     originalDueDate = 01-Jan-2026
     frequency = 1 Week
     missedCycles = 3
     
     skippedDates = [
       08-Jan-2026  (originalDue + 1 week)
       15-Jan-2026  (originalDue + 2 weeks)
       22-Jan-2026  (originalDue + 3 weeks)
     ]

   IMPORTANT: Do NOT include originalDueDate itself in the 
   skipped dates list. The originalDueDate is already represented 
   by the actual work order being completed (just very late).

3. For each skipped date, INSERT one record into 
   component_maintenance_history with:
     - componentId: the component ID
     - jobId: the job ID
     - workOrderId: null (no actual WO for skipped cycles)
     - vesselId: the vessel ID
     - dateCompleted: the skipped cycle date (formatted DD-MMM-YYYY)
     - status: 'SKIPPED'
     - workDescription: 'Maintenance cycle not performed — 
                         automatically recorded as SKIPPED'
     - performedBy: null
     - approvedBy: null
     - missedCycles: 0
     - isSkipped: true
     - skippedCycleDate: the skipped cycle date (same as dateCompleted)
     - sourceWorkOrderId: workOrderId (the ID of the WO that was 
                          completed late, triggering this backfill)
     - originalDueDate: the skipped cycle date

4. Log to console how many skipped records were created:
   console.log(`[BACKFILL] Created ${skippedDates.length} SKIPPED 
   cycle records for job ${jobId}, triggered by WO ${workOrderId}`)
