# Prompt for Replit: Full PMS Trial Test (No UI Changes)

You are QA’ing a maritime **Planned Maintenance System (PMS)** web app.
**Do not change any UI (HTML/CSS/layout/styles) or labels.**
Your job is to verify **end-to-end functionality** and that **all data is persisted in the database**.

## 0) Test Constraints

* **No UI edits.** If something is unclear or blocked, leave a note—do not “fix” UI.
* Prefer **Playwright** (or Cypress) for E2E/browser tests, **pytest** for API/service tests, and a lightweight **DB verification script** (SQL/ORM) for persistence checks.
* Produce artifacts: screenshots for each happy path, a junit/HTML test report, and a short README of findings.

## 1) Environment & Smoke

1. Start app with default config; confirm **database is created/migrated** (tables exist).
2. Verify health endpoint (if any) returns OK.
3. Create an **admin** and **crew user** (Chief Engineer, 2nd Engineer, Chief Officer/Master) to test role behavior.

**DB checks:** schema exists; connection works; migrations applied. Save the schema snapshot.

---

## 2) Module Coverage & Expected Behaviors

### A) Components

**Goal:** components are the master equipment records.

* Add a component with all fields (Maker, Model, Serial, Codes, Category, Location, Critical flag, Dates, Rating/Condition, Dept, Parent, Dimensions, Notes).
* Update **Running Hours section** values and **Condition Monitoring metrics** with thresholds.
* Attach Work Orders (linked list visible), Spares, Drawings/Manuals (file upload), Class/Regulatory data, Regulations.
* **Search and filters** in the left tree work; selecting a node filters correctly.

**Persistency:** all fields stored; files linked; relationships (WO/spares/documents) exist.

### B) Work Orders

Two-part form (A & B). Roles: assigned rank fills, HoD approves.

**Create/execute flow**

1. Create Scheduled WO (title, component, frequency OR running-hour based, category, priority, assigned to, approver, description).
2. Add **Required Spares** (with current ROB status), **Tools**, **Safety** requirements, **Work History** visible.
3. Fill **Part B** after execution: risk assessment flags+uploads, start/completion date/time, team size, manhours, work carried out, notes, **Running Hours** (mandatory for RH-based), **Spares Consumed**.
4. Save → **status becomes Pending Approval**.
5. Log in as **Chief Engineer/Chief Officer/Master** → Approve and Reject once each (separate WOs):

   * On **Approve** → WO moves to **Completed** and becomes **immutable** (verify fields are read-only).
   * On **Reject** → verify reasons recorded and WO returns for correction.

**List page checks:** All/Due/Pending Approval/Overdue/Completed tabs, search, period, ranks, component, criticality filters; sorting; pagination.

**Persistency:** WO header, Part B, consumption ledger, status transitions, approvals captured with timestamp/user.

### C) Running Hours

List shows Component, Category, **Running Hours**, **Last Updated**, **Utilization Rate**, **Update RH** button.

**Individual update**

* **Set Total**: enter new total; date+comments mandatory; verify new value and utilization rate.
* **Add Delta**: add increment; date+comments mandatory; verify correct total.
* **Meter Replaced**: mark as replaced; verify the reset event is recorded and future calculations use the new baseline.

**Bulk update**

* Use both **Set Total** and **Add Delta** modes across multiple components; confirm per-row results and validation (no negatives).

**Persistency:** per-update log entries with mode, old/new values, user, date, comments; meter-replacement event stored.

### D) Spares

Inventory grid with component tree filter; columns: Part Code, Part Name, Component, Spare Code, Critical, **ROB**, **Min**, **Stock**, **Location**, **IHM**, **Actions**.

**Flows**

* **Add Spare** (unique code, linked component, criticality, ROB, Min, Location, IHM Presence+Evidence).
* **Consume (−)** and **Receive (+)** single-row actions with mandatory comments/dates.
* **Bulk Update**: header (date/place/comments) + per-row Consumed/Received → ROB recalculated.
* **History tab**: Opening Balance, Receipt, Consumption, Adjustment are **append-only**.
* **Status logic**: OK (ROB ≥ Min), Low (0 < ROB < Min), Empty (ROB = 0).

**Persistency:** spare, links to components, history ledger, ROB math, IHM metadata.

### E) Stores (Stores / Lubes / Chemicals / Others)

* Add items (code, name, category, UOM, ROB, Min, Location, IHM).
* Row **Consume/Receive**, **Bulk Update**, **Export**, filters (Category/Stock).
* **History** is immutable.

**Persistency:** items saved per tab; ROB updates; IHM metadata.

### F) Modify PMS (Change Requests)

* From **Modify PMS → New Change Request**, navigate to:

  * **Work Orders**: open an existing WO, change **Frequency 6 months → 3 months**. Changed fields show **in red** before submission. Add reason/comments. Save.
  * Confirm request appears on **Modify PMS dashboard** as **Pending**.
* Login as office role; **Approve** and **Reject** once each:

  * On **Approve**: verify the live WO updates to **3 months** and red changes resolve.
  * On **Reject**: request stores rejection reason; no change applied.
* Ensure all change requests are permanently logged.

**Persistency:** old/new values, requester, timestamps, decision, approver, reason.

### G) Admin

1. **Bulk Data Import**

   * Download templates (Components/Stores/Spares).
   * Fill a tiny sample sheet and upload.
   * Verify rows created, with per-row error reporting for bad data (e.g., duplicate codes, missing mandatory fields).
2. **Alerts Configuration**

   * Enable Maintenance Due, Critical Inventory, Running Hours Threshold, Certificate Expiration; set Email/In-App and Priority.
   * Configure **Quiet Hours** and **Escalation**.
   * Trigger sample conditions (e.g., set a WO due soon; set a spare below Min) and verify alerts are generated, delivered, acknowledged/escalated per rules.
3. **Forms Control**

   * Change a non-breaking form attribute (e.g., make a field mandatory) **only in the Admin test sandbox**, not the live UI layout, and verify a **new form version** is logged with date/version number.
   * Ensure older records still open with their historical version.

**Persistency:** import logs, alert policy records + alert events, form version table with diffs.

---

## 3) Cross-Cutting Checks

* **Search boxes, dropdowns, filters, sorters, pagination**: verify functional in every list.
* **Validation**: mandatory fields enforced; numeric ranges; uniqueness (Part Codes/Item Codes).
* **Relationships**: no orphan records (e.g., WO must reference a component).
* **Immutability rules**:

  * Approved Work Orders & Work History entries are read-only.
  * Spares/Stores **History** is append-only.
* **RBAC**: crew can create/submit; HoD/office can approve/reject; unauthorized edits blocked.
* **Data export** buttons generate usable files.
* **Error handling**: friendly messages for duplicates, missing fields, invalid dates, negative ROB, etc.

---

## 4) Database Verification (must-pass)

Write a small script (SQL/ORM) to assert:

* Tables exist and have rows after each action (components, work\_orders, work\_order\_history/partB, running\_hours\_log, spares, spare\_history, stores, store\_history, change\_requests, alerts, alert\_events, forms\_versions, attachments).
* Key invariants:

  * No negative ROB.
  * Unique codes (components/spares/stores).
  * Work Orders in **Completed** state have an approval record.
  * Change requests store **old\_value/new\_value** per field.
  * “Meter replaced” events exist when flagged and are linked to the component.

Export a **DB snapshot** (or queries output) into the report.

---

## 5) Deliverables

* Automated test suite (Playwright/Cypress + pytest) runnable with one command.
* **JUnit/HTML** report + **screenshots** for each main flow.
* **DB verification output** (queries + results).
* **Issues list** with repro steps and severity (Blocker/Major/Minor).
* Short **README**: how to run tests, environment variables, and what was verified.

**Reminder:** Do not modify any UI (no CSS/HTML/labels/layout). Report problems; don’t “fix” them.
