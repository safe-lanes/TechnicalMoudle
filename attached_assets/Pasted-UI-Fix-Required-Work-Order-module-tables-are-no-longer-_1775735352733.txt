UI Fix Required: Work Order module tables are no longer filling the available table width after the previous column-resize fix

The earlier resize issue may be resolved, but a new UI glitch has been introduced.

Current problem
In the WO module tables, the table now stops before the right edge of the available container and leaves a large blank area on the right side. This is wrong.

Expected layout behavior:

The leftmost column must stay aligned to the left edge of the table container.

The rightmost visible column must extend up to the right edge of the table container whenever total column widths are less than available space.

The table should use the full available width of the table wrapper by default.

If the user resizes columns so total width becomes greater than container width, then horizontal scroll is fine.

In short:
minimum table width = container width

actual table width = max(container width, sum of visible column widths)
Right now, it looks like the table width is being set only to the sum of visible column widths, which causes the whole table to shrink and leaves empty space to the right. That behavior is not acceptable.
What I want you to fix

Please fix this for all tables in the Work Order module, not just the currently visible one.
That means any shared table logic, reusable table component, or all WO submodule tables using this column-width behavior must follow the same rule consistently.
Root cause to investigate

I suspect the previous fix did this:


removed w-full

set the table width equal to the sum of the visible column widths

enabled horizontal scrolling
That solved the “both edges moving” issue, but introduced another one:

when summed column widths are less than the available wrapper width, the table no longer stretches to fill the wrapper

so the last column ends too early

leaving blank dead space on the right side
This means the logic must be changed from:
ts
tableWidth = sumOfVisibleColumnWidths

to:
ts
tableWidth = Math.max(containerWidth, sumOfVisibleColumnWidths)

But do not blindly apply only that line — rework the layout properly so the visual behavior is correct in all WO tables.
