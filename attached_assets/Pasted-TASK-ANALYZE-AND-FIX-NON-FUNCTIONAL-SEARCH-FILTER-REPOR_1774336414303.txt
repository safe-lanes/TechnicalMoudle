TASK: ANALYZE AND FIX NON-FUNCTIONAL SEARCH FILTER – REPORT SECTION

Objective:

Identify why the **Search Filter in Reports Section is not working** and provide a **detailed corrective implementation plan**.

--------------------------------------------------

1. Current Issue

• When entering any keyword in the search field:
  - No filtering is applied  
  - Report data remains unchanged  
• Expected behavior: Only matching records should be displayed  

--------------------------------------------------

2. Required Analysis

Perform detailed analysis on the following layers:

A. UI Layer

• Verify if search input is:
  - Capturing user input correctly  
  - Triggering any event (onChange / onEnter / onSearch)  
• Check if search value is passed to backend/API  

--------------------------------------------------

B. API / Service Layer

• Verify if search parameter is:
  - Included in API request payload/query params  
  - Properly named and mapped  

• Check if backend endpoint supports search filtering  

--------------------------------------------------

C. Backend Logic

• Verify if search logic is implemented in:
  - Query layer (SQL / ORM)  
  - Service layer  

• Check:
  - Is WHERE clause applied?  
  - Is LIKE / ILIKE / full-text search implemented?  
  - Are correct columns included in search?  

--------------------------------------------------

D. Data Binding

• Verify if filtered data is:
  - Returned correctly from API  
  - Bound to UI grid/table  

--------------------------------------------------

3. Root Cause Identification

Identify if issue is due to:

• Missing API parameter  
• Incorrect parameter mapping  
• Backend query not implemented  
• UI not refreshing after search  
• Debounce or event trigger issue  

--------------------------------------------------

4. Corrective Implementation Plan

A. UI Fix

• Ensure search input triggers API call:
  - On Enter key OR  
  - On debounce (300–500 ms)

• Pass search keyword as parameter:
  example: `?search=<keyword>`

--------------------------------------------------

B. API Update

• Update API to accept search parameter  
• Validate parameter presence  

--------------------------------------------------

C. Backend Query Fix

• Implement filtering logic:

  - Use LIKE / ILIKE for partial matching  
  - Apply across relevant columns (e.g., name, code, description)

Example:

WHERE  
  column1 ILIKE '%keyword%' OR  
  column2 ILIKE '%keyword%'  

--------------------------------------------------

D. Multi-Column Search

• Ensure search applies across:
  - Report Name  
  - Component Name  
  - Spare Name  
  - Codes / IDs  

--------------------------------------------------

E. Performance Optimization

• Add indexing on searchable columns  
• Use pagination to limit result size  

--------------------------------------------------

F. UI Refresh

• Ensure UI updates with filtered results  
• Reset pagination to page 1 after search  

--------------------------------------------------

5. Testing Plan

Validate with:

• Exact keyword match  
• Partial keyword match  
• Case-insensitive search  
• No match scenario (empty result)  
• Large dataset performance  
• Combined filters (search + date + dropdown)

--------------------------------------------------

6. Expected Result

• Search filter works correctly  
• Only matching records are displayed  
• Fast and responsive filtering  
• Consistent behavior across all reports
