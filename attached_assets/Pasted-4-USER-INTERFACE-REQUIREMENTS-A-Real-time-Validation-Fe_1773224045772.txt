5. BACKEND API ENDPOINTS:

A. GET /api/pms/running-hours/valid-range

Purpose: Calculate and return valid RH range for a given completion date

Query Parameters:

machineryId: ID of the machinery/component

completionDate: The date user is trying to complete work order for

Response:

javascript
{
  minRH: Number,
  maxRH: Number,
  previousEntry: {
    date: Date,
    runningHours: Number,
    source: String
  },
  nextEntry: {  // null if no future entry exists
    date: Date,
    runningHours: Number,
    source: String
  },
  recommendedAction: String  // "USE_CURRENT", "MANUAL_ENTRY_REQUIRED", etc.
}
B. POST /api/pms/running-hours/validate

Purpose: Validate a proposed RH entry before saving

Request Body:

javascript
{
  machineryId: String,
  completionDate: Date,
  runningHours: Number
}
Response:

javascript
{
  isValid: Boolean,
  validationStatus: String,  // "VALID", "INVALID_BACKWARD", "INVALID_FORWARD", "HIGH_UTILIZATION"
  errorMessage: String,      // Detailed error if invalid
  validRange: {
    min: Number,
    max: Number
  },
  utilizationRate: Number,   // Hours per day average
  requiresJustification: Boolean,
  anomalyFlags: [String]     // Array of anomaly types if any
}
C. GET /api/pms/running-hours/timeline

Purpose: Get complete RH timeline for a machinery

Query Parameters:

machineryId: ID of the machinery

dateFrom (optional): Start date for timeline

dateTo (optional): End date for timeline

Response: Array of all RH entries sorted chronologically

D. GET /api/pms/running-hours/current

Purpose: Get current RH value from RH Module

Query Parameters:

machineryId: ID of the machinery

Response:

javascript
{
  currentRH: Number,
  lastUpdated: Date,
  source: "RH_MODULE",
  updatedBy: String
}
E. POST /api/pms/work-orders/:workOrderId/complete

Purpose: Complete work order with validated RH

MODIFIED BEHAVIOR:

Accept runningHours in request body

Call validation endpoint first

If validation fails: Return error, do not save

If validation passes with warning: Require rhJustification field

Save completionRH to work order (NOT to RH Module)

Create entry in rhTimeline collection

If high utilization: Create anomaly entry

NEVER update the RH Module collection

7. RH MODULE ISOLATION ENFORCEMENT:

CRITICAL RULE: The RH Module must be the ONLY place where actual current running hours can be updated.

Implementation Strategy:

A. Remove Write Access from Work Order Module:

Remove any code in work order completion logic that updates the RH Module collection

Work orders should ONLY write to their own completionRH field

Work orders should ONLY add entries to rhTimeline for audit purposes

B. Add Database-Level Protection (if possible):

Set up database permissions/triggers to prevent work order module from writing to RH Module collection

Only RH Module service should have write permissions

C. API Gateway Protection:

All RH Module update APIs should check the calling service

Reject updates from work order module

Only allow updates from RH Module interface

D. Audit Trail:

Log every attempted RH update with source information

Flag any unauthorized update attempts

Send alert to admin if work order tries to update RH Module

8. MIGRATION AND EXISTING DATA HANDLING:

For Existing Work Orders:

When implementing this system, there may be existing work orders with RH data that was entered without validation:

Migration Steps:

Create rhTimeline collection

Import all RH data from RH Module history → add as entries with source "RH_MODULE"

Import all RH data from completed work orders → add as entries with source "WORK_ORDER"

Sort chronologically

Run validation check on all existing work order RH entries

Flag any entries that fail validation as "HISTORICAL_INVALID"

Generate report of invalid entries for admin review

Add these to anomaly dashboard as "LEGACY_DATA_ISSUE"

Backward Compatibility:

Old work orders without completionRH field: Show "RH not recorded" in UI

Don't break existing reports/analytics that use RH data

Provide migration period where validation is WARNING-only (not blocking)
