Great question! Here's how location change works for spares in this system:

The Dual-Location Model

Each spare has two location "slots" -- Location A (location field) and Location B (location2 field). These are simple text fields that store a location name (like "ENGINE ROOM STORE" or "BRIDGE DECK LOCKER"). A spare can have stock at one or both of these locations.

What "Changing Location" Means

When you change a spare's location from the Location tab, you're telling the system: "Move all the stock this spare has at Location X over to Location Y." For example, moving 5 units from "ENGINE ROOM STORE" to "BRIDGE DECK LOCKER."

How It Works (3-Step Process)

Remove stock from the current location -- the system records an inventory adjustment removing all units from the old location
Update the spare's location name -- the spare's location or location2 field is updated to reflect the new location name (this is necessary because the inventory system validates that the location name matches what's on the spare record)
Add stock to the new location -- the system records an inventory adjustment adding those same units to the new location
Slot Detection

The system automatically figures out which slot (A or B) corresponds to the location you're currently viewing. It does this by comparing the selected location's name against the spare's location and location2 fields. Only that slot gets updated -- the other one stays untouched.

Safety Checks

If the spare has no stock at the current location, the change is blocked
If neither location slot matches the current location name (rare edge case), the operation is blocked with a clear message
If any step fails partway through, the system attempts to undo the previous steps to keep data consistent
All stock movements are logged as ADJUST_CORRECTION events in the inventory history for audit purposes
Key Limitation

This is a client-side orchestrated process (not a single atomic backend transaction), so in rare cases of network interruption mid-transfer, some manual reconciliation might be needed. The system does its best to roll back on failure though.
