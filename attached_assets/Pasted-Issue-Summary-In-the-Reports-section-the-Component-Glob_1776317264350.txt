Issue Summary

In the Reports section, the Component Global Filter is not behaving consistently:

In the right-side view (UI display) → the filter is not applied, and all component data is still visible.
In Export (PDF/Excel) → the filter is applied correctly, showing only the selected component data.
Detailed Investigation
1. Behavioral Gap

There is a clear inconsistency between:

UI Rendering Layer (Right-side View)
Export Processing Logic (PDF/Excel)

This indicates that:

The filter state is being captured correctly (since export works).
But the UI view is not reacting to the applied filter state.
2. Possible Root Causes (UI-Level)
a. Filter State Not Bound to View Refresh
The selected component is stored, but the data grid is not reloaded or re-rendered after selection.
The UI continues to display previous/unfiltered dataset.
b. Missing Event Trigger
The filter selection does not trigger:
Data refresh
Grid re-binding
State update propagation
c. Separate Handling of Export vs View
Export is likely using the latest filter state directly.
UI view is dependent on manual or implicit refresh, which is currently missing.
d. Global Filter Scope Not Propagated
The global filter is not being applied uniformly across all report components on screen.
Some UI components may not be subscribed to the global filter state.
e. Caching / Stale Data Issue
The UI may be displaying cached data, ignoring updated filter inputs.
Apply Filter Button – Analysis
Current Observation
Filter selection does not immediately reflect in UI.
This suggests absence of a trigger mechanism.
Conclusion

An “Apply Filter” button is recommended if:

Multiple filters are used together
Controlled execution is required
Avoiding frequent reloads is important

Otherwise:

The system should support auto-apply on selection, but only if:
Proper event binding and refresh logic is implemented
Recommended Approach
Prefer auto-apply with proper trigger handling
Add Apply button only if performance or multi-filter complexity requires it
Corrective Measures
1. Ensure Filter-to-View Binding
The global component filter must be directly linked to all report views
Any change in filter should:
Update state
Trigger UI refresh
2. Implement Data Refresh Trigger
On component selection:
Force data reload or re-binding
Ensure UI reflects latest filtered dataset
3. Standardize Filter Behavior Across Views
Align:
UI display logic
Export logic
Both should consume the same filtered dataset source
4. Remove Stale Data Rendering
Clear previous dataset before applying new filter
Prevent UI from showing unfiltered cached data
5. Validate Global Filter Scope
Ensure all report widgets:
Recognize the global filter
Apply it only if relevant fields exist
6. Optional: Introduce Apply Filter Mechanism
If needed:
Add Apply button
Prevent partial or inconsistent filtering
Clearly define:
When filter is applied
When data refresh happens
Task Breakdown for Fix
Task 1: Filter State Validation
Verify component selection is correctly stored and updated
Task 2: UI Binding Correction
Link filter state with report view rendering logic
Task 3: Trigger Implementation
Add event trigger on filter change to refresh UI
Task 4: Data Sync Alignment
Ensure UI and export use same filtered dataset logic
Task 5: Scope Validation
Confirm filter applies only to reports with component field
Task 6: UI Refresh Handling
Implement proper clearing and reloading of data on filter change
Task 7: Apply Button Decision
Evaluate need and implement if required
Expected Outcome
Filter behaves consistently across:
UI view
Export outputs
Real-time reflection of selected component in reports
No mismatch between displayed and exported data
