Add Job Button
Location
Found in Section C (Jobs) of the Components page
Button text: "Add Job" with Plus icon
What Happens When Clicked
Navigates to: /pms/work-order/new/{componentCode}?mode=template
The componentCode from the currently selected component is passed in the URL
The ?mode=template query parameter is critical - it changes the form behavior
Job Form (WorkOrderFormPage.tsx)
Mode Detection
The form has 4 possible modes:

template - Creating/viewing a job template (Section A only)
execution - Filling out a work order (Section A + B)
history - Viewing completed work order history
new - Creating a brand new job/work order
Mode is determined by:
1. URL query param: ?mode=template
2. Route prop: mode prop passed from router
3. Default: 'execution' if nothing specified

Template Mode (Add Job) - Section A Only
Navigation Sections
When mode=template:

navSteps = [{ id: 'part-a', label: 'A', title: 'Job Details' }]

Only Section A is shown - no Section B (Work Completion Record)

Section A Fields (Job Template)
Field	Description
WO Title / Job Title	Name of the job
Component	Pre-filled from URL componentCode
Component Name	Display name
Component Code	SFI code
WO Template Code	Job number (e.g., MKR-IN-001)
Maintenance Basis	"Calendar" or "Running Hours"
Frequency Value	Number (e.g., 6)
Frequency Unit	"Months", "Days", "Weeks", "Years" (Calendar) or "Hours" (RH)
Task Type	"Inspection", "Overhaul", "Service", "Testing"
Assigned To	Default assignee (rank)
Approver	Default approver (rank)
Job Priority	"Low", "Medium", "High", "Critical"
Class Related	"Yes" / "No"
Department	Equipment department
Criticality	Criticality level
Is Active	"Yes" / "No"
Brief Work Description	Job instructions
Next Due Date	Calendar-based due date
Next Due Reading	RH-based due reading
Required Spare Parts	Array of parts needed
Required Tools	Array of tools needed
Safety Requirements	PPE, permits, other requirements
Execution Mode - Section A + B
Navigation Sections
When mode !== template:

navSteps = [
  { id: 'part-a', label: 'A', title: 'Job Details' },
  { id: 'part-b', label: 'B', title: 'Work Completion Record' }
]

Section A Behavior in Execution Mode
Read-only - Part A is a "frozen snapshot" of the job template
Cannot be edited because it was copied from the template when the work order was generated
Section B Fields (Work Completion)
Field	Description
Risk Assessment	Document upload
Safety Checklists	Document upload
Operational Forms	Document upload
Start Date/Time	When work began
Completion Date/Time	When work finished
Running Hours	Current RH at completion
Performed By	Who did the work
No of Persons	Crew involved
Total Time Hours	Duration
Manhours	Total manhours
Work Carried Out	Description of completed work
Job Experience Notes	Lessons learned
Consumed Spare Parts	Parts actually used
Data Flow Summary
Add Job Button Clicked
        ↓
Navigate to /pms/work-order/new/{componentCode}?mode=template
        ↓
WorkOrderFormPage loads in TEMPLATE mode
        ↓
Only Section A displayed (editable)
        ↓
User fills job details, frequency, safety requirements, etc.
        ↓
On Save → POST to /api/jobs
        ↓
New job appears in Component's Section C (Jobs list)

Key Differences: Template Mode vs Execution Mode
Aspect	Template Mode (Add Job)	Execution Mode (Work Order)
Sections shown	A only	A + B
Section A editable	Yes	No (frozen)
Section B shown	No	Yes
Purpose	Define job template	Complete work order
Save endpoint	/api/jobs	/api/work-orders
Data source	User input	Loaded from generated WO
