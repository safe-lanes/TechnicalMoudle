## 1️⃣ What this setting is & what we want to achieve

**Goal:**
Give each client/company a place in **Admin** to define:

* **Lead time** → how early a Work Order should be generated **before** a job is actually due.
* **Grace period** → how far **beyond** due we allow for escalation (NOT for status; status still becomes overdue as soon as due is reached).

This will control **automatic WO generation** for:

* **Calendar-based jobs** (weekly/monthly/annual)
* **Running-hour–based jobs** (e.g., every 500 RH)

These values become the **key driver** in the WO generation logic instead of hard-coded numbers.

---

## 2️⃣ From where it will get the data

Data sources:

* **Jobs table**

  * `job_id`, `component_id`, `job_type` (CALENDAR / RH), `frequency_value`, `frequency_unit` (days/weeks/months/hours), `critical_flag`, `last_done_date`, `last_done_rh`, etc.

* **Running Hours module**

  * For RH jobs:

    * Parent component `current_rh`.

* **Admin → PMS Settings (new screen)**

  * Global / per-vessel **Lead Time + Grace configuration**, e.g.:

  **For calendar jobs:**

  * `calendar_lead_days_critical`
  * `calendar_lead_days_noncritical`
  * `calendar_grace_mode`:

    * `COMPANY_STANDARD` (end-of-month / 1 week rule)
    * or `CUSTOM_DAYS`
  * `calendar_grace_days` (used if CUSTOM)

  **For RH jobs:**

  * `rh_lead_hours_critical`
  * `rh_lead_hours_noncritical`
  * `rh_grace_hours` (default 168h, configurable)

We can also support **per-vessel override** later, but first version can be **global for the company**.

## 3️⃣ How the functionality will work

### 3.1 Calendar-based jobs – Lead Time & Grace

For each calendar job:

* `due_date = last_done_date + frequency`
* From Admin settings:

  * `lead_days = calendar_lead_days_critical` if job is critical
    else `calendar_lead_days_noncritical`
  * `grace_window`:

    * If `calendar_grace_mode = COMPANY_STANDARD`

      * We apply your company rule (end-of-month / 1 week).
      * Can be implemented internally as:

        * If due date is in last week of month → `due_date + 7 days`
        * Else → `end of that month`.
    * If `CUSTOM_DAYS` → `due_date + calendar_grace_days`

**When to generate WO:**

* When `today >= due_date - lead_days`
  → **Generate WO** if no active WO exists.

**Status:**

* If `today < due_date` → WO status: **DUE** (future-due)
* If `today >= due_date` → WO status: **OVERDUE**
  (Grace does NOT change status; only escalation logic.)

---

### 3.2 Running-hour jobs – Lead Time & Grace

For RH jobs:

* `due_rh = last_done_rh + frequency_hours`
* Current RH from parent component: `current_rh`
* From Admin:

  * `lead_hours = rh_lead_hours_critical` if job critical
    else `rh_lead_hours_noncritical`
  * `grace_hours = rh_grace_hours` (default 168h, configurable)

**When to generate WO:**

* When `current_rh >= due_rh - lead_hours`
  → **Generate WO** if no active WO exists.

**Status:**

* If `current_rh < due_rh` → WO status: **DUE**
* If `current_rh >= due_rh` → WO status: **OVERDUE**
  (Grace hours only used for escalation & alerts to office.)

Sections:

     * Critical jobs: [input number]

   * Grace Period:

     * Mode: [ Company Standard | Custom days ]
     * If Custom: [input number of days]

2. **Running-Hour Jobs Settings**

     * Critical jobs: [input number]
     * Non-critical jobs: [input number]
   * Grace Period:

     * [input number of hours] (default 168)

3. **Preview / Help box**

   * “Based on these values, WOs will be generated this early and escalated after this grace period.”

All values stored in a `PmsSettings` table and read by:

* **WO generation service** (calendar scheduler or trigger).
* **RH update handler** (for RH-based jobs).

>
