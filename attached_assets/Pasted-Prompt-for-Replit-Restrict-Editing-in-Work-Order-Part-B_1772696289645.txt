Prompt for Replit – Restrict Editing in Work Order Part B After WO Completion

Module

Work Order Form → Part B – Work Completion Record

Objective

When the Work Order (WO) status is marked as “Completed”, the Part B – Work Completion Record section must become read-only. No editing or modification should be allowed.

Conditions for Restriction

Apply the following restrictions only when:

work_order.status = 'Completed'
1. Block Editing of Part B Fields

When the WO status is Completed:

All fields under Part B – Work Completion Record must become read-only.

Users should not be able to:

Modify text fields

Change checkboxes

Update dropdown values

Modify entered data

UI behavior:

Fields should appear disabled or greyed out to indicate read-only status.

2. Block Upload Function

Attachment upload option must be disabled or hidden.

Users must not be able to upload new files once the WO is completed.

Allowed actions:

View attachment

Download attachment

3. Block Spare Part Addition

When WO status is Completed:

The Add Spare Part button must be disabled or hidden.

Users must not be able to:

Add new spare parts

Modify spare quantities

Remove existing spare entries

Existing spare records should remain visible for reference only.

4. Allowed Actions After Completion

Even after completion, users should still be able to:

View all data in Part B

View attachments

Download attachments as PDF

Print or download the Work Order PDF

5. Backend Validation (Mandatory)

Add backend validation to prevent unauthorized edits:

If API receives update request and:

work_order.status = 'Completed'

Then:

Reject the request

Return validation error:

"Editing is not allowed because the Work Order is completed."

This prevents bypassing UI restrictions.

6. Expected Final Behavior

When WO status = Completed:

Part B fields → Read-only

Upload option → Blocked

Add Spare Part → Blocked

Existing attachments → View / Download allowed

Work Order PDF → Accessible

Important

Ensure:

No partial editing loopholes exist.

Backend validation is enforced even if frontend is bypassed.

UI clearly indicates read-only state to the user.
