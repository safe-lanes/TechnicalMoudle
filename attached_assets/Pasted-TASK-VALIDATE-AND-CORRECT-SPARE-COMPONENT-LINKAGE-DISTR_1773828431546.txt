TASK: VALIDATE AND CORRECT SPARE–COMPONENT LINKAGE DISTRIBUTION LOGIC

Objective:

Verify whether the current **Spares Bulk Import → Spare_Component_Linkage distribution logic** is working as per requirement.  
If not, provide a **detailed corrective implementation plan**.

--------------------------------------------------

Expected Logic:

1. Distribution Scope

• Spares should be linked **ONLY to the components explicitly provided in the Excel template**  
• No linkage should be created for:
  - Parent components  
  - Auto-derived hierarchy components  
  - Any unrelated components  

--------------------------------------------------

2. Entry Count Validation

• The total number of records created in **Spare_Component_Linkage table** must be:

  → EXACTLY equal to the number of valid rows in the Excel template  

• No additional or derived entries should be created  

--------------------------------------------------

3. Validation Requirements

Verify the following:

• Is the system creating linkage only for Excel-provided Component Codes?  
• Is it incorrectly expanding linkage to parent or related components?  
• Is the total count of linkage records matching Excel row count?  
• Are duplicate linkage entries being created?  
• Is any transformation logic altering the intended mapping?

--------------------------------------------------

4. If Current Logic is Incorrect — Provide Fix Plan

A. Root Cause Identification

• Identify where extra linkages are getting introduced:
  - Backend service logic  
  - Mapping layer  
  - Bulk import processing logic  
  - Database triggers (if any)  

--------------------------------------------------

B. Corrective Logic Design

• Modify linkage creation logic as follows:

  1. Read each row from Excel  
  2. Extract:
     - Spare Identifier (Part Code / Spare Code)  
     - Component Code (ONLY from Excel row)  
  3. Validate:
     - Component exists  
     - Spare exists or is created  
  4. Create EXACTLY ONE linkage per row:
     - No hierarchy traversal  
     - No parent/child auto-linking  

--------------------------------------------------

C. Deduplication Control

• Add validation to prevent:

  - Duplicate (Spare + Component) entries  
• Use unique constraint or pre-insert check:
  (Spare_ID + Component_ID + Vessel_ID)

--------------------------------------------------

D. Data Integrity Enforcement

• Ensure:

  - No orphan linkages  
  - No linkage without valid component  
  - No linkage across vessels  

--------------------------------------------------

E. Vessel-Based Validation

• Ensure linkage is created only within the **selected vessel context**  
• Prevent cross-vessel linkage creation  

--------------------------------------------------

F. Count Validation Logic

• After import:

  - Count Excel valid rows  
  - Count inserted linkage rows  

• If mismatch:

  - Log error  
  - Return validation message  

--------------------------------------------------

G. Error Handling

Provide clear errors for:

• Invalid Component Code  
• Missing Spare Code  
• Duplicate rows in Excel  
• Failed linkage creation  

--------------------------------------------------

H. Testing Plan

Validate with:

• Single row import  
• Multiple rows with same spare different components  
• Duplicate entries in Excel  
• Invalid component rows  
• Mixed valid and invalid data  

--------------------------------------------------

Expected Result:

• Spare_Component_Linkage table contains ONLY entries from Excel  
• Entry count EXACTLY matches Excel rows  
• No parent/child auto-linking  
• No duplicate or extra records  
• Clean, controlled, and predictable linkage behavior
