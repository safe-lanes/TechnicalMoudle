Move "Superintendent" from Sidebar to Dashboard Tile

CONTEXT:
The "Superintendent" page (at /pms/superintendent) was added to the left sidebar during Layer 5 implementation. However, this clutters the sidebar navigation with a feature that is not frequently used by most users. The Superintendent Notifications page is primarily for shore-based superintendents to acknowledge late/skipped work orders — most vessel crew don't need quick access to it.

WHAT TO CHANGE:

STEP 1 — Remove "Superintendent" from the Sidebar

In client/src/components/SideMenuBar.tsx (or wherever the PMS sidebar menu items are defined), remove the "Superintendent" menu item completely. Do not delete the route or page — only remove it from the sidebar navigation.

The sidebar should go back to showing only:

Dashboard

Components

Work orders

Running Hrs

Spares

Stores

Reports

Modify PMS

Admin

STEP 2 — Add a "Superintendent Notifications" Tile to the Dashboard

In client/src/pages/pms/Dashboard.tsx (or wherever the PMS dashboard is rendered), add a new dashboard tile for Superintendent Notifications.

The tile should be placed in the existing dashboard grid (wherever the other tiles like "Work Orders", "Components", "Running Hours" are displayed).

Tile Design:

text
Title: "Superintendent Notifications"
Icon: 🛡️ (shield) or a flag icon
Background color: Light red/orange (#fff4e6 or similar) if there are pending notifications, light grey if none
Tile Content (2 metrics):

text
Large number (top): [Total Pending Acknowledgment count]
Label: "Pending Acknowledgment" (red text if > 0)

Smaller number (below): [Acknowledged This Month count]
Label: "Acknowledged This Month" (green text)
Click behavior:
When the tile is clicked, navigate to /pms/superintendent (the full Superintendent Notifications page).

Data source:
Fetch the counts from the existing GET /api/superintendent/notifications API endpoint (the one that returns unacknowledged notifications). You can derive:

Pending Acknowledgment count = count of items where isAcknowledged = false

Acknowledged This Month count = count of items where isAcknowledged = true AND acknowledgedAt is within the current month

If these exact counts aren't already returned by the API, either:

Add a new lightweight endpoint like GET /api/superintendent/notifications/summary that returns just {pendingCount, acknowledgedThisMonthCount}, OR

Fetch the full notification list and count client-side (only do this if the list is small — if there could be hundreds of notifications, create the summary endpoint)

Tile should only be visible if the user has superintendent/shore-side role OR if there are any pending notifications.
If there are 0 pending notifications and the user is a vessel crew member (not a superintendent), you can optionally hide the tile completely. Use whatever role/permission logic you already have in place for showing the Superintendent page.

STEP 3 — Verify

After implementing:

Confirm the "Superintendent" item is gone from the left sidebar

Go to /pms/dashboard → confirm a new tile appears showing "Superintendent Notifications" with the pending/acknowledged counts

Click the tile → confirm it navigates to /pms/superintendent

The tile should update its counts if a superintendent acknowledges a notification (you can test this by acknowledging one of the test WOs from Layer 5, then going back to the dashboard)
