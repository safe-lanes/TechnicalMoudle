ISSUE 1: DASHBOARD - VESSEL FILTER NOT WORKING CORRECTLY
═══════════════════════════════════════════════════════════

PROBLEM DESCRIPTION:
The Dashboard's "INVENTORY & FLEET ANALYSIS" panel on the right side is showing data from MULTIPLE vessels even when a SPECIFIC vessel is selected in the vessel dropdown.

CURRENT BEHAVIOR (WRONG):
1. User selects "Vessel 11" from the vessel dropdown (as shown in screenshot)
2. The right panel shows a table with colored dots for different categories:
   - Work Orders (with colored dots)
   - Overdue WOs (with colored dots)
   - Low Stock (with colored dots)
   - Spares (with colored dots)
   - Running Hrs (with colored dots)
3. When hovering over these dots, it shows data from RANDOM/MULTIPLE vessels
4. The panel is displaying aggregated data from ALL vessels, NOT just Vessel 11

This is a CRITICAL data integrity issue - users expect to see ONLY the selected vessel's data.

EXPECTED BEHAVIOR (CORRECT):
The dashboard panel data MUST respect the vessel filter selection:

SCENARIO A: Specific Vessel Selected (e.g., "Vessel 11")
- All data in the panel should ONLY show Vessel 11's data
- Work Orders count: Only from Vessel 11
- Overdue WOs: Only from Vessel 11
- Low Stock items: Only from Vessel 11
- Spares status: Only from Vessel 11
- Running Hours issues: Only from Vessel 11
- No dots or data from other vessels should appear

SCENARIO B: "All Vessels" Selected
- Show combined/aggregated data from ALL vessels
- Multiple vessels can be represented with dots/indicators
- Hovering shows which vessel each data point belongs to
- This is the ONLY scenario where multi-vessel data should appear

IMPLEMENTATION REQUIREMENTS:

1. VESSEL FILTER INTEGRATION:
   - The Dashboard must watch the vessel dropdown selection state
   - When vessel changes, ALL panels and data must update to show only that vessel's data
   - Apply vessel filter to ALL API calls and data queries

2. DATA FILTERING LOGIC:
   Current (Wrong):
   - Queries fetch data from ALL vessels
   - Frontend displays all data without filtering by selected vessel
   
   Required (Correct):
   - Add vessel_id filter to ALL dashboard data queries
   - Example API calls:
     GET /api/dashboard/work-orders?vessel_id=11
     GET /api/dashboard/spares-status?vessel_id=11
     GET /api/dashboard/inventory?vessel_id=11
   - When "All Vessels" is selected, use vessel_id=all or omit the filter

3. PANEL DATA FILTERING:
   The right panel sections must filter by vessel:
   
   "INVENTORY & FLEET ANALYSIS" section:
   - Total Spares: Count from selected vessel only
   - Low Stock: Items from selected vessel only
   - Critical Low Stock: Items from selected vessel only
   - Total Components: Count from selected vessel only
   - Stores Inventory: Count from selected vessel only
   
   "SPARES STOCK STATUS" donut chart:
   - OK/At Min/Low: Calculated from selected vessel only
   
   Table with colored dots (Work Orders, Overdue WOs, Low Stock, Spares, Running Hrs):
   - ONLY show rows/data for the selected vessel
   - Remove dots representing other vessels
   - When "All Vessels" selected, show all vessels with colored dots

4. LEFT PANEL FILTERING:
   The left panel sections must also filter by vessel:
   
   "WORK ORDER KPIS":
   - Overdue WOs: Count from selected vessel only
   - Completion Rate: Calculated from selected vessel only
   - Outstanding Tasks: From selected vessel only
   
   "WORK ORDER STATUS & TRENDS":
   - Status Distribution pie chart: Selected vessel only
   - Trend line graph: Selected vessel only
   
   "OVERDUE WORK ORDERS" table:
   - List only work orders from selected vessel

5. DATABASE QUERY EXAMPLE:
   
   Before (Wrong - no vessel filter):
   ```sql
   SELECT COUNT(*) FROM work_orders WHERE status = 'overdue'
After (Correct - with vessel filter):

sql
SELECT COUNT(*) FROM work_orders 
WHERE status = 'overdue' AND vessel_id = :selectedVesselId
