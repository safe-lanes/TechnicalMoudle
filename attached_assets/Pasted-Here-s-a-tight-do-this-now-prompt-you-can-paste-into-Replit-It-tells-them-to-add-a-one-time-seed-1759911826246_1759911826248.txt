## 🔧 Prompt: Seed 10 defects (5 identical equipment) to test Recurring & Persistence

**Goal**

* Create **10** defect records in the live dev DB (not in-memory).
* **5** of those must share the exact same **Category / Type / Make / Model** so they aggregate into **one Recurring Defects group** (occurrence ≥ 2 within last 12 months).
* Mix of **Open** and **Closed**, at least **one CoC**, across **multiple vessels**.
* Include **one same-day same-vessel near-duplicate** to exercise de-duplication.
* Data must survive server restart (use the app’s existing DB/persistence layer).

---

### 1) Add a one-time seed entry point

Implement **one** of the following (whichever matches our stack):

* **Script:** `npm run seed:defects` (or `python seed_defects.py`)
* **OR** a protected dev route: `POST /dev/seed/recurring-defects` (idempotent: safe to call twice)

The seed must **upsert** by a stable client id (e.g., `seedId`) so we don’t duplicate on re-run.

### 3) Mapping to our fields

When inserting, map JSON keys to our model:

* `equipment.category → Category`
* `equipment.type → Type`
* `equipment.make → Make`
* `equipment.model → Model`
* Compute/Store `equipment_key` exactly as in production (`normalize("${category}|${type}|${make}|${model}")`)
* Other fields: `vesselName`, `issuedDate`, `targetDate`, `status` ("open"/"closed"), `isCoC`, `description`, `actionRequested`, `source`, `defectCategory`, `defectType`, `responsibleRole`.

**Persist to the real DB** (SQLite/Postgres/Mongo—use whatever the app already uses). Do **not** use in-memory mocks.

---

### 4) Verify (manual QA steps)

1. Refresh the **Defects → Active** list: you should see many of the seeded rows (open ones).
2. Open **Defects → Recurring Defects** (12-month window):

   * Expect **one group** for **Pumps & Valves › Sea Water Pump › DESMI › NSL 200-265**
   * **Occurrences** ≥ 4 (5 minus 1 if dedup triggers)
   * **Vessels affected** ≥ 3 (SEAFARER, VOYAGER, OCEANIC, ATLANTIS)
   * **Open defects** ≥ 2 (depending on which are open)
   * **CoC** badge = **true** (RD-002)
3. Restart the server → data remains (persistence OK).
4. Close one of the open DESMI pump defects, then check **Resolved** tab and that the recurring group’s **open count** updates.

---

### 5) Safety / idempotency

* Seed must be **idempotent**: re-running should **update** existing by `seedId`, not create duplicates.
* Provide a way to **wipe the seed set** (`npm run seed:defects:reset` or `DELETE /dev/seed/recurring-defects`) for clean re-tests.
