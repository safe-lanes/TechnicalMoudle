Task: Fix passive Period filter binding for API-sourced reports

Issue
There is a critical bug in the PMS Reports module: the global Period filter is passive for several API-sourced reports. Reports such as:

Critical Equipment Status

Unplanned/Breakdown Jobs

show no data even when valid data exists and even when all vessels are selected. This indicates that the selected Period is either not being passed correctly to the report API calls, not being consumed by the backend, or not being used correctly in the final response filtering.

Objective
Fix the binding between the global Period filter and all affected API-sourced reports, so that selecting a time range correctly updates report data without requiring a page refresh.

Required fix
Please do the following only:

Identify all reports in the Reports module that load data from dedicated APIs rather than only frontend-local filtering.

Check how the global Period filter state is passed from the Reports page to these report components.

Verify whether the selected date range is being included in the API request parameters.

Verify whether the backend endpoints/controllers/services are actually reading and applying the date range.

Fix the full filter chain so that:

Period selected in the global filter bar

is passed to the child report component

is sent to the API request

is consumed by backend logic

and filters the returned dataset correctly

Specifically ensure this works for:

Critical Equipment Status

Unplanned/Breakdown Jobs

Ensure that when the user clicks Apply on Period, the reports update immediately in the UI without page refresh.

Ensure empty states appear only when there is genuinely no data for the selected period.

Important implementation note
This issue is specifically about API-sourced reports, so please focus on reports where data is fetched from backend endpoints and the Period filter may be disconnected in that request/response flow.

The fix must ensure that:

Period is not just displayed in the UI

Period is not just used in report subtitle/header

Period actively controls the actual dataset returned for the report

Expected behavior
After the fix:

selecting a valid Period should refresh the affected reports automatically

Critical Equipment Status should show data for the selected time range if matching data exists

Unplanned/Breakdown Jobs should show data for the selected time range if matching data exists

reports should no longer stay blank because of broken Period binding

no manual page refresh should be required

Output required after fix

which files were changed

confirmation that Period is now properly bound end-to-end for the affected API-sourced reports
