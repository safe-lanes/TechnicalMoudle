# 1) Active

**Purpose:** Show all *open* defects that require attention.

**Definition of “Active”**

* `status IN {Open, Pending, In-Progress, Awaiting Parts, Deferred}`
* NOT closed; NOT cancelled.

**Route & State**

* Route: `/defects/active`
* Default tab on first landing to Defects.
* Persist query (period/vessel/fleet/type/additional filters) in URL params and local storage.

**Header/Toolbar**

* The existing top filters (Period, Search, Vessel, Fleet, Add Group, Due/Overdue, Type, Apply/Clear) remain.
* “Include Closed Defects” checkbox is **forced OFF** and disabled on Active view.

**Table Columns (no change)**

* ID, Vessel, Issue Date, Category, Description, Action Taken/Requested, Target Date, Date Completed (empty for active), Status, Actions.

**Badges / Counters**

* Badge on the left icon: number of active defects (capped at 99+). Update after any create/edit/close.

**Actions allowed (row level)**

* View 👁, Edit ✏️, Add Note/Paperclip 📎, Link 🔗 (if you support linking to WOs), Delete 🗑 (role-gated), Close/Complete ✅ (if user has permission).
* Overdue indicator shown when `today > target_date` and `status != Closed`.
* SLA/Countdown hover: “Due in X days” / “Overdue by X days” (existing clock icon behavior).

**Empty state**

* Show “No active defects match your filters” with buttons: **Clear Filters** and **+ New Defect**.

**API**

* `GET /api/defects?status=active&...`
  Server interprets `status=active` to the set above.

# 2) Resolved

**Purpose:** Show *closed* (historical) defects; immutable records.

**Definition of “Resolved”**

* `status IN {Closed, Cancelled}` (final states)
* `date_completed` set (for Closed).

**Route & State**

* Route: `/defects/resolved`
* Persist filters in URL/local storage independently from Active tab.

**Header/Toolbar**

* Same filter bar; **Include Closed Defects** is **forced ON** and disabled (you’re already in a closed view).
* Add optional quick filter pill: **Completion Period** (derived from Period).

**Table**

* Same columns; `Status` shows a green “Closed” or grey “Cancelled”.
* `Date Completed` populated; `Target Date` retained for KPI (to compute early/on-time/late).

**Immutability**

* All edit controls disabled; only **View** and **Export Row** (if you support row export) enabled.
* “Re-open” (if you want later) should be role-gated and logged as a change request (Phase 2).

**Export**

* Toolbar “Export” (CSV/XLSX/PDF) respects current filters.

**API**

* `GET /api/defects?status=resolved&...`

---

# 3) Reports

**Purpose:** Pivot and summarize defects for management/KPI.

**Route**

* Route: `/defects/reports`

**Layout**

* Left: Report pickers (cards or list)
* Right: Filter panel (Vessel, Fleet, Period, Category, Type, Due/Overdue, Severity (VIQ), Source, Port/At-Sea state, Routine/Breakdown, Reported To (Class/Flag/Port), Deferment Only, etc.)
* Primary CTA: **Run Report**; Secondary: **Export** (CSV/XLSX/PDF).

**Starter Report Set (matches your PMS reporting style)**

1. **Open Defects Dashboard**

   * KPIs: Total Open, Due this month, Overdue, Avg age (days), Top 5 categories, By vessel/fleet.
   * Table: current open list (like Active view) under the charts.

2. **Closure Performance**

   * KPI: Median days to close, % closed on/before target, % overdue at closure.
   * Breakdowns: by vessel, by department (Deck/Engine), by responsible role (Chief Eng/Master/Office).
   * Trend line: monthly closures vs. overdue closures.

3. **Root Cause Analysis**

   * Heatmap: Immediate Cause vs. Root Cause (Unsafe Act/Condition vs. System/Individual factors).
   * Top frequent root causes, vessel drill-down.

4. **Deferments Log**

   * Table & KPI: Count of deferred items, avg deferment days, reasons.
   * Filter `deferment_flag=true`.

5. **Regulatory & Third-Party Reporting**

   * Count sent to Class/Flag/Port, statuses, outcomes (if captured).
   * Exportable list with references.

6. **Aging Report**

   * Buckets: 0–7, 8–30, 31–60, 61–90, >90 days open.
   * By vessel and category.

7. **VIQ/SFI Reference Utilization**

   * Defects by VIQ ref and SFI code (for audits).

**Charts**

* Use your existing component charting; no style changes. Respect dark/light if present.

**Export**

* Each report offers CSV/XLSX and PDF.
* Export filename pattern: `Defects_<ReportName>_<YYYYMMDD>_<VesselOrFleet>.{csv|xlsx|pdf}`.

**API**

* `POST /api/defects/reports/{reportKey}` with filter payload.
* Server returns `{kpis, series, table}`.

## Shared Behaviors & Data

**Status Model**

* `Open` → `In-Progress` → `Awaiting Parts` → `Deferred` → `Closed` (or `Cancelled`)
* Only `Closed/Cancelled` appear in **Resolved**.
* “Deferment Needed (Y/N)” toggles `Deferred` state and requires “Deferment Reason” (Phase 2).

**Permissions**

* View: all ship/office roles with module access.
* Edit/Close/Delete: role-gated (e.g., Chief Eng/Master onboard; Tech Superintendent in office).
* Resolved: immutable (no edits).

**Counts & Alerts**

* Sidebar badges refresh after CRUD, and on a 60s poll or WebSocket event.
* Hook to Alerts config (you already have global alerts):

  * Maintenance Due → also support **Defect Overdue** notifications.

**Deep Links**

* Row View → `/defects/{id}/view` (read-only, your “View” screen).
* Edit → `/defects/{id}/edit`.

**Empty States**

* Each section shows helpful empty-state with CTA to **+ New Defect** or **Adjust Filters**.

**Performance**

* Server-side pagination (default 25).
* Keep current infinite scroll/next page pattern, if any.

## Minimal DB/Backend Notes (no schema break)

* Reuse `defects` table. Add if not present:

  * `status`, `date_completed`, `deferment_flag`, `deferment_reason`, `reported_to` (enum: Class/Flag/Port/None), `operating_state` (enum: Sailing/Port/Anchor), `routine_breakdown` (enum), `raised_by_user_id`, `target_date` (rename label only in UI).
* Views:

  * `active_defects_v` (WHERE status NOT IN (‘Closed’, ‘Cancelled’))
  * `resolved_defects_v` (WHERE status IN (‘Closed’, ‘Cancelled’))
