Please fix the PMS Reports export output so that the generated PDF and Excel match the cleaned view mode exactly. Right now, in Vessel 11, the reports that are exported as PDF/Excel are still including the old summary/tile sections such as SUMMARY blocks, total counts, critical counts, class item counts, due soon counts, and similar report overview tiles. That is wrong. The exported files must reflect the same cleaned report layout that the user sees in the right-pane view mode after the redesign.

This is the key requirement: the exported report content must be the same as the visible report view content, not the old legacy printable template that still contains summary tiles and extra report overview sections.

At present, there is a mismatch between:

the redesigned on-screen report viewer, and

the generated PDF/Excel output.

That mismatch must be removed. The user should not see one version in the PMS Reports screen and receive a different older version in the export file.

What is wrong now
In reports such as “CRITICAL EQUIPMENT STATUS REPORT,” the exported file is still including old summary sections like:

SUMMARY

Total Critical Equipment

Critical Only

Class Item Only

Both Critical & Class

With Overdue Jobs

Due Soon (7 days)

That kind of summary tile/block content is exactly what we have been trying to remove from the reports UI. If it is removed from view mode, it must also be removed from the exported PDF and Excel. The exported file should not continue to use the old legacy report format.

The same applies to other reports such as Low Stock Alert and similar report families if they still export old summary/tile content instead of the simplified report body.

Main rule to implement
Please make export generation use the same cleaned report data presentation as the visible right-pane report viewer.

That means:

If the on-screen report no longer shows the summary tile section, the PDF must also not show it.

If the on-screen report no longer shows the summary badge strip, the Excel must also not include it as a separate summary block.

If the on-screen report starts directly with the actual report table/content, the exported files must also start directly with the actual report table/content.

In short: view mode is the source of truth for export layout.

Desired export behavior
For every report in PMS Reports:

The report opens in the right pane in clean view mode.

The user clicks Export PDF or Export Excel.

The exported file should contain the same logical content structure as the right-pane view.

No old summary tiles, summary cards, summary counters, or overview blocks should reappear in the exported file unless they are intentionally visible in the actual cleaned view.

What to remove from export templates
Please remove old export-only summary sections from the generated files, including but not limited to:

“SUMMARY” headings,

total count blocks,

critical count blocks,

class item count blocks,

due soon count blocks,

overdue count blocks,

warning/info/anomaly count badges,

any summary row or badge block that is not part of the cleaned view mode.

Do not allow export templates to continue using old report print layouts if those layouts no longer match the redesigned UI.

period if needed,

generated date/time if needed,

column headers,

actual report rows,

But remove the legacy summary/tile layer that sits between the title and the real report table.

So for example:

It is fine if the export contains a simple report heading and metadata line.

It is not fine if the export contains an old summary dashboard block before the table.

If some minimal metadata is required in the exported report, keep it minimal and aligned with the cleaned viewer, for example:

report name,

vessel,

report period,

generated timestamp,

generated by.
