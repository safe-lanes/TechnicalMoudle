Raplit Prompt — Copy Vessel (Components) Validation Enhancement
Module

PMS → Fleet & Vessel Manager → Copy Vessel → Components

🎯 Objective

Enhance the existing Copy Vessel – Components functionality by adding field-level copy restrictions.

Current behavior correctly replicates component data from Source Vessel to Target Vessel.

Now introduce validation to exclude specific runtime and meter-related fields during replication.

📌 Change Type

Backend Validation Adjustment

No UI change
No workflow change
No permission change

⚙️ Updated Copy Logic Requirement

When copying components from:

Source Vessel → Target Vessel


The system must:

Replicate structural and configuration data

Exclude operational runtime and meter tracking fields

🚫 Columns That Must NOT Be Copied

The following fields from the components table must be excluded during replication:

installation_date
commissioned_date
running_hours
current_cumulative_rh
last_updated
rh_current_master
rh_master_updated_at
rh_master_updated_by
rh_master_update_source
rh_current_inherited_cached
rh_inherited_updated_at
meter_replaced_date
meter_replaced_last_rh


⚠ Note:
current_cumulative_rh was listed twice — ensure it is excluded once.

🔎 Expected Behavior for Excluded Fields

For the Target Vessel:

These fields must be:

Set to NULL
OR

Set to default value (as per system standard)

They must NOT inherit values from the Source Vessel.

🧠 Rationale

These fields represent:

Operational runtime tracking

Meter history

Master RH sync metadata

System-updated timestamps

Equipment lifecycle information

Copying them would corrupt vessel-specific operational history.

🧩 Data Integrity Rules

Do not alter primary keys

Do not copy audit metadata

Maintain component hierarchy integrity

Ensure no carryover of RH master linkage

🧪 Validation Checklist

After copy:

Structural tree must replicate correctly

Component codes must match source

Runtime-related fields must be NULL/default

No duplicated meter history

No RH master reference carryover
