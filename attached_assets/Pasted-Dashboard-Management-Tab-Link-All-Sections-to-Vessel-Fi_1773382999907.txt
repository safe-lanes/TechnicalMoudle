Dashboard Management Tab - Link All Sections to Vessel Filter

text
CRITICAL ISSUE: Dashboard Management Tab Not Respecting Vessel Filter

PROBLEM DESCRIPTION:
The Dashboard's Management tab contains several sections that are NOT properly linked to the vessel dropdown filter selection. These sections show data from OTHER vessels or ALL vessels even when a SPECIFIC vessel is selected.

USER'S EXAMPLE:
- Selected Vessel: "Vessel 8" (via vessel dropdown)
- Vessel 8 has NO data (all metrics show 0%, as confirmed in Fleet Comparison table)
- However, the "Superintendent Notifications" section shows:
  "1 Pending Acknowledgment" and "1 Acknowledged This Month"
- This notification data is from OTHER vessels, NOT Vessel 8

This is a CRITICAL data integrity issue - users expect ALL dashboard sections to show ONLY the selected vessel's data.

═══════════════════════════════════════════════════════════
SECTIONS THAT MUST BE LINKED TO VESSEL FILTER:
═══════════════════════════════════════════════════════════

The Management tab contains these sections that MUST respect the vessel filter:

1. SUPERINTENDENT NOTIFICATIONS
   - Shows pending acknowledgments and acknowledged items
   - Currently shows ALL vessels' notifications
   - MUST show only selected vessel's notifications

2. COMPLIANCE ANOMALY DETECTION
   - Cycle Skip Rate
   - Backdating Frequency
   - Bulk Completion Events
   - Schedule Drift
   - Currently shows data from all vessels
   - MUST show only selected vessel's anomalies

3. WORK ORDER ANOMALIES
   - Shows work order irregularities
   - Currently shows all vessels
   - MUST show only selected vessel's anomalies

4. FLEET COMPARISON TABLE (Already showing all vessels - this is CORRECT)
   - This table should ALWAYS show all vessels for comparison
   - This is the ONLY section that should show all vessels regardless of filter
   - No changes needed here

═══════════════════════════════════════════════════════════
EXPECTED BEHAVIOR:
═══════════════════════════════════════════════════════════

SCENARIO A: Specific Vessel Selected (e.g., "Vessel 8")

When user selects "Vessel 8" from dropdown:

SUPERINTENDENT NOTIFICATIONS:
- Show ONLY notifications related to Vessel 8
- If Vessel 8 has no pending acknowledgments → Show "No notifications"
- If Vessel 8 has no data → Show "No notifications" (NOT other vessels' data)
- Count only Vessel 8's pending/acknowledged items

COMPLIANCE ANOMALY DETECTION:
- Show ONLY anomalies detected for Vessel 8
- Cycle Skip Rate: Vessel 8 only
- Backdating Frequency: Vessel 8 only
- Bulk Completion Events: Vessel 8 only
- Schedule Drift: Vessel 8 only
- If Vessel 8 has no anomalies → Show "Insufficient data" or "No anomalies detected"

WORK ORDER ANOMALIES:
- Show ONLY work order anomalies for Vessel 8
- If no anomalies for Vessel 8 → Show "No anomalies detected"
- Do NOT show other vessels' anomalies

FLEET COMPARISON TABLE:
- ALWAYS show all vessels (no change needed)
- This table is for comparing vessels side-by-side
- Vessel filter does NOT affect this section

─────────────────────────────────────────────────────────

SCENARIO B: "All Vessels" Selected

When user selects "All Vessels":

ALL SECTIONS:
- Show combined/aggregated data from ALL vessels
- Superintendent Notifications: All vessels' notifications
- Compliance Anomalies: All vessels' anomalies
- Work Order Anomalies: All vessels' anomalies
- Fleet Comparison: All vessels (same as always)

═══════════════════════════════════════════════════════════

1. VESSEL FILTER STATE MANAGEMENT:
   - The vessel dropdown selection must be passed to ALL Management tab sections
   - Each section must watch for vessel filter changes
   - When vessel changes, ALL sections must refresh with new vessel's data

2. API ENDPOINT MODIFICATIONS:

   SUPERINTENDENT NOTIFICATIONS:
   Current (Wrong):
   GET /api/dashboard/superintendent-notifications

   GET /api/dashboard/superintendent-notifications?vessel_id=all

   COMPLIANCE ANOMALY DETECTION:
   Current (Wrong):
   GET /api/dashboard/compliance-anomalies
   
   Required (Correct):
   GET /api/dashboard/compliance-anomalies?vessel_id=8

   WORK ORDER ANOMALIES:
   Current (Wrong):
   GET /api/dashboard/work-order-anomalies
   
   Required (Correct):
   GET /api/dashboard/work-order-anomalies?vessel_id=8

3. BACKEND DATABASE QUERY MODIFICATIONS:

   All queries for Management tab sections (except Fleet Comparison) must add vessel filter:

   Example for Superintendent Notifications:
   
   Before (Wrong - no vessel filter):
   ```sql
   SELECT COUNT(*) as pending_count
   FROM superintendent_notifications
   WHERE status = 'pending'
After (Correct - with vessel filter):

sql
SELECT COUNT(*) as pending_count
FROM superintendent_notifications
WHERE status = 'pending'
AND vessel_id = :selectedVesselId
Example for Compliance Anomalies:

Before (Wrong):

sql
SELECT * FROM compliance_anomalies
WHERE detected_at > :startDate
After (Correct):

sql
SELECT * FROM compliance_anomalies
WHERE detected_at > :startDate
AND vessel_id = :selectedVesselId
