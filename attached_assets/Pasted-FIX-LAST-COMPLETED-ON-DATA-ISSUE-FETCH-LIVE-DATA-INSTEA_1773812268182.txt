FIX "LAST COMPLETED ON" DATA ISSUE - FETCH LIVE DATA INSTEAD OF HARDCODED VALUES
PROBLEM IDENTIFIED
There is a critical data accuracy issue with the "Last Completed On" and "Last Completed At RH" fields that were recently added to Part A - Job Details section of the Work Order Form.

Evidence of the Issue:

Work Order: MKR-IN-00073-702.005.02-2026-004 (Vessel 11)
Component: FO PURIFIER, NO.2 (702.005.02)
Job: FO PURIFIER, OIL CHANGE - 250H

What the system is showing:

Part A displays: "Last Completed On: 14-Aug-2015 (10 years ago)"

What the actual data shows:

A4 Work History section shows: An entry dated 31-Aug-2015 (2015-08-31)

This is 17 days MORE RECENT than the date shown in "Last Completed On"

Conclusion: The "Last Completed On" field is displaying incorrect hardcoded or corrupted data instead of fetching the actual most recent completion date from the database.

ROOT CAUSE ANALYSIS
The issue suggests one of the following problems:

Hardcoded/Cached Data: The "Last Completed On" field may be pulling from a pre-calculated or cached field in the database that contains old/incorrect data, rather than querying the actual completed work orders dynamically.

Incorrect Query Logic: The query fetching the last completion may have wrong sorting, filtering, or is not fetching the true most recent entry.

Data Migration Issues: During data import or migration to Vessel 11, the "last completed date" field may have been populated with incorrect values that don't match the actual work history.

REQUIRED FIX
OBJECTIVE:
Ensure that the "Last Completed On" (for calendar jobs) and "Last Completed At" (for RH jobs) fields in Part A ALWAYS display live, accurate data by querying the actual completed work orders from the database in real-time, NOT from pre-populated or cached fields.

IMPLEMENTATION REQUIREMENTS
A. Remove Hardcoded/Cached Data Dependency
Current (WRONG) Implementation:
The system may be fetching "Last Completed On" from a pre-populated field like:

job.lastCompletedDate or job.lastDoneDate from the Jobs table

component.lastMaintenanceDate from the Components table

Any other cached/stored field

Required (CORRECT) Implementation:
The system MUST fetch the last completion date by querying the actual WorkOrders collection dynamically every time the work order form is opened.

B. Correct Query Logic
When displaying "Last Completed On" or "Last Completed At RH" in Part A, use the following logic:

For Calendar-Based Jobs:

Query: Search the WorkOrders collection for:

componentId = current work order's component ID

jobCode = current work order's job code

status = "Completed"

Sort by completedAt or completionDate in DESCENDING order (most recent first)

Limit: 1 result

Exclude: The current work order itself (if viewing a completed work order, don't count it as the "previous" completion)

Extract: The completedAt or completionDate field from the result

Display: Format as "DD-MMM-YYYY (X days/months/years ago)"

Handle Empty: If no previous completion exists, display "Never completed" or "First cycle"

For Running Hours-Based Jobs:

Query: Same as above, but also extract the completedAtRH or completionRH field

Display: Format as "X,XXX Hours (on DD-MMM-YYYY)"
