There is a bug where the A4 Work History section on the Work Order form page always shows "No data available" even after a work order has been approved and marked as completed.

What is happening:

We completed and approved a WO: ME MOMENT COMPENSATOR, CHECK - 1W (WO code: MKR-IN-00008-601.001-2026-001)

The WO status is now "Completed" — the blue banner at top says "This Work Order is completed. Part B is read-only."

But Section A4 "Work History" shows "No data available" — completely empty

This means the maintenance history record is not being saved to the database when a WO is approved

What should happen:
When a WO is approved by the CE and marked as Completed, a new entry should be automatically created in the maintenance history table with the following data:

DATE: the completion date entered by the crew (e.g., 10-Mar-2026)

WORK ORDER: the WO number/code (e.g., MKR-IN-00008-601.001-2026-001)

DESCRIPTION: the "Work Carried Out" text entered by the crew in B2

PERFORMED BY: the rank selected in the "Performed by" field in B2

STATUS: "Completed"

REMARKS: "574 cycles skipped — completed late" (if missedCycles >= 1) OR "Completed on time" (if missedCycles === 0)

How to debug this:

Step 1 — Find where in the backend the approval logic runs. This is likely in server/modules/work-orders/services/workOrderService.ts around the approval path (when status changes to "Completed"). Look for where it tries to create a history/maintenance record.

Step 2 — Check if a maintenance history record is actually being inserted into the database at approval time. Add a console.log or check if there are any silent errors being swallowed. The history table is likely called maintenance_history or similar — check your database schema.

Step 3 — Check what jobCode or jobId is being used to link the history record to the job. The WO being tested is linked to job code MKR-IN-00008 and component code 601.001. If the jobId is null or mismatched, the history record may be created but not showing for this WO.

Step 4 — Check how the frontend reads and displays A4 Work History. Specifically: what query or API call does it use to fetch history records? What filter does it apply — by jobId, jobCode, or woId? Make sure the filter used to WRITE the record matches the filter used to READ/DISPLAY it.

Step 5 — Check workOrderCompletionService.ts and workOrderBulkService.ts as well — if these also have approval paths, they may also be missing the history write.

The fix:
Make sure that when a WO is approved, a history record is ALWAYS created with all the fields listed above. The REMARKS field must automatically include:

"${missedCycles} cycles skipped — completed late" when missedCycles >= 1

"Completed on time" when missedCycles === 0
