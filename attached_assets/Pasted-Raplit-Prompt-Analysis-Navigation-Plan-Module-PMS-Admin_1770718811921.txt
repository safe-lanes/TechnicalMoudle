Raplit Prompt — Analysis & Navigation Plan

Module: PMS → Admin → Fleet Data → Fleet Job Management
Scope: Edit Fleet Job Navigation & Screen Behavior
Change Type: Navigation + Screen Reuse (No Data / Logic Change)

Context

In Fleet Job Management, when a user attempts to edit any Fleet Job, the system behavior is currently inconsistent or unclear.

Both:

Fleet Job Management list

Edit Job Details page

are fetching data from the same table (fleet_jobs).

Because the data source and structure are the same, the Edit Job Details screen must be reused rather than creating or rendering a different UI.

Current Issue

Clicking Edit from Fleet Job Management does not reliably navigate to the proper Edit Job Details page

Navigation flow after Save or Back is not clearly defined

Screen reuse logic is not clearly enforced even though both pages use the same dataset

Expected Correct Behavior
1. Edit Navigation

When user clicks Edit on any Fleet Job from Fleet Job Management screen:

System must navigate to Edit Job Details page

The Edit Job Details screen must load:

The selected Fleet Job

Using the same layout, sections, and fields (since same table is used)

2. Screen Reuse Principle

Edit Job Details page UI must be the same screen

No duplicate or alternate edit screens should exist

Only the context (source page) should differ

Back & Save Navigation Rules
Back Button

When user clicks Back from Edit Job Details page:

System must navigate to the previous page (Fleet Job Management screen)

Job list state (filters, pagination if any) must remain unchanged

Save Button

When user clicks Save:

Data is saved (existing behavior — not part of this prompt)

After save, system must navigate back to:

Fleet Job Management screen

Updated job should be reflected in the list

Analysis Focus Areas

How navigation context is currently passed from Fleet Job Management

Whether route/state information is lost during navigation

Why the system does not consistently return to the source screen

Whether multiple edit routes are defined unnecessarily

Constraints (Strict)

ANALYSIS & PLAN ONLY

NO schema changes

NO table changes

NO validation changes

NO business logic changes

NO UI redesign

Reuse existing Edit Job Details page

Do not affect other job-related workflows

Navigation must return to previous screen only
