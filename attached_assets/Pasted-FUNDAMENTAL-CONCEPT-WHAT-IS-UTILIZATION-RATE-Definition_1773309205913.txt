FUNDAMENTAL CONCEPT - WHAT IS UTILIZATION RATE?
Definition:
Utilization Rate represents "On average, how many hours per day was this machinery running during the selected time period?" expressed as a percentage of 24 hours (maximum possible daily operation).

Business Context:

100% utilization = Machinery ran continuously 24 hours/day for the entire period

50% utilization = Machinery ran on average 12 hours/day during the period

0% utilization = Machinery was not operated (or RH not updated) during the period

Key Principle:
The utilization rate is PERIOD-SPECIFIC. It shows utilization for ONLY the selected time window (Weekly/Monthly/Quarterly/Yearly), NOT the lifetime of the machinery.

CLEAR CALCULATION RULES
Rule 1: Basic Formula (Universal for All Periods)
text
Utilization Rate (%) = (Running Hours Accumulated in Period / Maximum Possible Hours in Period) × 100

Where:
Running Hours Accumulated = Current RH - RH at Start of Period
Maximum Possible Hours = Number of Days in Period × 24 hours/day

Then cap the result:
Final Utilization Rate = MIN(calculated rate, 100.0%)
Rule 2: Period Definitions (Fixed Time Windows)
Each period option represents a FIXED LOOKBACK WINDOW from today:

Period Selected	Days in Period	Maximum Possible Hours	Period Start Date Calculation
Weekly	7 days	7 × 24 = 168 hours	Today - 7 days
Monthly	30 days	30 × 24 = 720 hours	Today - 30 days
Quarterly	90 days	90 × 24 = 2,160 hours	Today - 90 days
Yearly	365 days	365 × 24 = 8,760 hours	Today - 365 days
Important: These are calendar-independent rolling windows. "Monthly" always means "last 30 days from today", NOT "this calendar month".

STEP-BY-STEP CALCULATION PROCEDURE
For EACH component in the Running Hours list, perform these steps:

Step 1: Identify the Period Parameters
Based on user's dropdown selection:

If "Weekly (7 days)" selected:

periodDays = 7

maxPossibleHours = 168

If "Monthly (30 days)" selected:

periodDays = 30

maxPossibleHours = 720

And so on...

Step 2: Calculate Period Start Date
text
Today = Current date (e.g., 12-Mar-2026)
Period Start Date = Today - periodDays

Examples:
- Weekly: 12-Mar-2026 - 7 days = 05-Mar-2026
- Monthly: 12-Mar-2026 - 30 days = 10-Feb-2026
- Quarterly: 12-Mar-2026 - 90 days = 12-Dec-2025
- Yearly: 12-Mar-2026 - 365 days = 12-Mar-2025
Step 3: Get Current Running Hours
text
currentRH = Component's current cumulative running hours

Source: components table → currentCumulativeRH field (or equivalent)

Example: FO PURIFIER, NO.1 → currentRH = 2,001 hrs
Step 4: Get Running Hours at Period Start
This is the CRITICAL STEP that requires clarification:

Query the running_hours_audit table:

text
Find the CLOSEST running hours entry that is:
- For this component (componentId match)
- On or BEFORE the Period Start Date
- Sorted by date descending (most recent first)
- Take the FIRST result

SQL Concept:
SELECT runningHours, date 
FROM running_hours_audit
WHERE componentId = [component_id]
  AND date <= [periodStartDate]
ORDER BY date DESC
LIMIT 1

Result: rhAtPeriodStart = value from this query
Edge Cases for Step 4:

Case A: Query returns a value

Use that value as rhAtPeriodStart

Example: Found entry from 08-Feb-2026 with RH = 1,950 hrs

rhAtPeriodStart = 1,950 hrs

Case B: Query returns NO results (no historical data before period start)

This means component was added recently OR has no audit history

Solution: Use the OLDEST available RH entry for this component

If NO audit entries exist at all → rhAtPeriodStart = 0

Case C: Component has currentRH = 0

rhAtPeriodStart = 0

Result will be 0% (correct - machinery not in operation)

Step 5: Calculate RH Accumulated in Period
text
rhAccumulated = currentRH - rhAtPeriodStart

Example:
currentRH = 2,001 hrs
rhAtPeriodStart = 1,950 hrs
rhAccumulated = 2,001 - 1,950 = 51 hrs
Edge Cases for Step 5:

Case D: rhAccumulated is NEGATIVE (RH decreased)

This happens when meter was reset/replaced

Solution: Set rhAccumulated = 0

Result: 0% utilization (cannot calculate utilization across meter reset)

Case E: rhAccumulated is ZERO

Machinery genuinely didn't run, OR

RH hasn't been updated in the period

Solution: Proceed with calculation (will result in 0%)

Step 6: Calculate Utilization Rate
text
utilizationRate = (rhAccumulated / maxPossibleHours) × 100

Example (Monthly period):
rhAccumulated = 51 hrs
maxPossibleHours = 720 hrs
utilizationRate = (51 / 720) × 100 = 7.08%
Step 7: Cap at 100%
text
IF utilizationRate > 100 THEN
  utilizationRate = 100.0
  Log warning: "Data quality issue - utilization exceeds 100%"
END IF
Why >100% can occur:

Incorrect RH entry (data error)

Missing intermediate audit records

System timestamps vs actual operation dates mismatch

Step 8: Round and Display
text
Display: Round to 1 decimal place

Examples:
7.08333% → Display as 7.1%
0.0% → Display as 0.0%
100.0% → Display as 100.0%

CRITICAL CLARIFICATIONS FOR REPLIT
Clarification 1: What "Monthly Utilization" Means
"Monthly Utilization Rate" answers this question:

"In the last 30 days, on average, how many hours per day did this machinery run?"

NOT:

"How much total RH does the machinery have?" (That's Current RH)

"How many times was RH updated this month?" (That's audit activity)

"What's the lifetime utilization?" (That would need different calculation)

Example Interpretation:

Monthly Utilization = 50% means:

In last 30 days, machinery accumulated 360 hours

Average: 360 ÷ 30 = 12 hours/day

12 hours is 50% of 24 hours/day

Therefore: 50% utilization

Clarification 2: The Role of "Last Updated" Date
The "Last Updated" column shows when the RH was last changed in the system.

Important: This is NOT directly used in utilization calculation!

Example:

Last Updated: 11-Mar-2026

But this doesn't mean RH CHANGED on 11-Mar

It just means someone RECORDED the RH on 11-Mar

The RH might have been the same value for weeks!

The calculation uses:

Period Start Date (calculated: Today - period days)

RH value at that period start date (from audit trail)

Current RH value

Clarification 3: Audit Trail is ESSENTIAL
For utilization calculation to work correctly, the system MUST have:

running_hours_audit table with:

Every RH change logged

Date/timestamp of when RH was recorded

The RH value at that time

Complete history:

Entries going back at least 365 days (for Yearly period)

Minimum: Entries going back 30 days for Monthly

If audit trail is incomplete:

Utilization rates will be inaccurate

May show 0% even when machinery is running

May show 100% for new components (if using 0 as baseline)

DIAGNOSTIC CHECKLIST FOR DEBUGGING
When utilization shows unexpected 0.0%, check these in order:

Check 1: Is Current RH = 0?
If YES → 0.0% is correct (machinery not in operation)

If NO → Continue to Check 2

Check 2: Does audit trail have data for this component?
sql
SELECT COUNT(*) FROM running_hours_audit 
WHERE componentId = [component_id]
If COUNT = 0 → No audit history (utilization will be wrong)

If COUNT > 0 → Continue to Check 3

Check 3: Is there an audit entry before period start date?
sql
SELECT * FROM running_hours_audit
WHERE componentId = [component_id]
  AND date <= [periodStartDate]
ORDER BY date DESC
LIMIT 1
If NO RESULT → No baseline for period (may use 0 or oldest entry)

If HAS RESULT → Check the RH value returned
