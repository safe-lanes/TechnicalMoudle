# 🔧 Replit Implementation Brief — Modern, Interactive PMS Dashboard

## 0) Constraints (must follow)

* **No new APIs**. Read data only from existing modules:

  * Components (A–H)
  * Work Orders (planned only)
  * Running Hours
  * Spares / Stores / Lubes / Chemicals (inventory + min/UOM/stock)
  * Reports (for counts you already compute)
* **Do not change any existing UI in other modules.** This is an additive dashboard.
* **All widgets are clickable** and navigate to the relevant filtered view in the existing module.

---

## 1) Global Controls (top bar)

* **Vessel selector** (left): “All Vessels” (default) + per-vessel list (same list you use in Components).
* **Date range** (right): presets = Last 7d, 30d, 90d, This Month, Last Month, YTD. Persist in localStorage.
* **Last updated** timestamp + “Refresh” icon.
* **Dark mode** toggle (persist in localStorage). Use existing color palette; no theme resets elsewhere.

*Filter behavior*: All widgets must re-query locally (same data cache) when vessel/date changes.

---

## 2) KPI Row (cards with mini-sparklines)

Four cards; each shows value, delta vs previous period, and a tiny sparkline from the same data:

1. **Active Work Orders**

   * value = count of planned WOs with status ≠ Completed within filter.
   * delta = vs previous equal period.
   * click ⇒ Work Orders list filtered by vessel/date/status=Active.

2. **Overdue Tasks**

   * value = count where DueDate < today and not completed.
   * card background slightly alert (soft red); icon = warning.
   * click ⇒ Work Orders filtered by Overdue.

3. **Completed This Period**

   * value = completed within date range.
   * click ⇒ Work Orders filtered by Completed + date range.

4. **Critical Stock Alerts**

   * value = count of inventory lines where `ROB < Min` OR flagged Critical.
   * click ⇒ Spares/Stores list with Low filter applied.

*Sparklines*: 12 points max (daily for 7/30, weekly for 90/YTD), no legends, tooltips on hover.

---

## 3) Charts (interactive, responsive)

### A) Work Orders by Status (Donut)

* Slices: Pending, In Progress, Completed, Overdue (planned only).
* Center label shows total.
* Click a slice ⇒ navigate to Work Orders with that status filter applied.

### B) Completion Trend (Area/Line)

* X = time buckets (daily or weekly per range), Y = completed count.
* Secondary (optional) subtle line = created count (to see backlog).
* Brush/zoom not needed; simple hover tooltip.

### C) Upcoming Maintenance Timeline (Stacked bar)

* Buckets: **Due in 7d**, **8–30d**, **>30d**; each bar stacked by **Critical vs Routine**.
* Clicking a segment ⇒ Work Orders with corresponding due window + priority.

### D) Inventory Health (Horizontal bars)

* Four bars: **Spares, Stores, Lubes, Chemicals**
* Each bar = total items; inner emphasized segment = items **below Min**.
* Click a bar ⇒ open that sub-module filtered to Low stock.

> Use a lightweight chart lib you already have (e.g., Chart.js/Recharts). Keep color mapping consistent with existing UI (green=good, amber=warn, red=overdue/low).

---

## 4) Smart Lists (drilldown panels)

### A) “Needs Attention” (left column)

* **Top 10 Overdue WOs** (title, component, due date, age in days).
* Row click ⇒ that WO detail.

### B) “Low Stock Items” (right column)

* **Top 10 items under Min** (code, name, UOM, ROB/Min, Location).
* Row click ⇒ that item in its module.

Both lists respect vessel/date filters and paginate if >10.

---

## 5) Inventory & Running Hours Quick Glance (compact widgets)

* **Running Hours**: for selected vessel, show current RH + last update date; click ⇒ Running Hrs screen.
* **Last 5 Receipts / Consumptions** (any inventory) with type, item, qty, date; click ⇒ History tab filtered.

---

## 6) Navigation & Interactions

* Every KPI, slice, bar, and list row **navigates to the existing screen** with filters pre-applied via your current URL query conventions (e.g., `?vessel=V1&status=overdue&range=last30`).
* Back button returns to dashboard with the same vessel/date preserved.

---

## 7) Performance & UX

* Cache raw data per vessel/date in memory for the session; invalidate on “Refresh”.
* Skeleton loaders for each widget; no blocking spinners.
* Accessible: keyboard focus, ARIA labels for charts, sufficient contrast.
* Fully responsive: 4-column desktop → 2-column tablet → single-column mobile.

---

## 8) Data Mapping (from existing modules)

* **Work Orders**: status, due date, completed date, created date, priority (Critical/Routine), vessel.
* **Inventory**: category (spares/stores/lubes/chemicals), UOM, ROB, Min, Critical flag, location, vessel.
* **Running Hours**: current RH + last updated per vessel.
* **Reports**: where you already compute counts, reuse them (no new SQL).

*No schema changes, no new endpoints. If something is unclear, ask; do not invent fields.*

---

## 9) Visual Style (match your app)

* Cards: soft shadow, rounded md, compact padding.
* Colors: use existing OK/Low/Overdue palette (green/amber/red).
* Icons: your current set (don’t import new packs).
* Dark mode: invert neutrals; keep semantic colors readable.

---

## 10) Acceptance Criteria

* Vessel selector + date range control affect **every** widget.
* All numbers reconcile with the underlying lists they link to.
* Each widget clickable to the relevant filtered page.
* No layout shifts; responsive works down to 1280→768→375 widths.
* No changes to other modules’ UIs or APIs.
