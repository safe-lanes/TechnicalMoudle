Implementation Plan: Low Stock Alert Report (NO Purchase Module Dependencies)

Phase 1: Backend Enhancement
1.1 New Storage Method
Add to server/storage.ts:

ts
getLowStockAlertReport(vesselId, filters) => {
  summary: { totalAlerts, criticalCount, warningCount, valueAtRisk },
  items: LowStockAlertItem[]
}
Query logic (use only existing PMS data):

Base tables: spares (master), current ROB/stock table, any existing consumption / transaction history that already exists.
​

If sparesHistory with CONSUME events (last 90 days) exists, use it; if not, skip rate-based fields for now.
​

Calculations (only if data exists; otherwise return null for that field):

avgDailyConsumption: If history exists, average daily consumption over last 90 days; else null.

daysBelowMin: Count consecutive days where ROB ≤ min (only if you have daily snapshots or equivalent; else null).

reorderQty: max(0, min - rob) for now (no lead time multiplier since there is no purchase module yet).

priorityScore: (criticalityWeight * 3) + (shortagePercent * 2) + (daysBelowMinWeight * 1) where:

criticalityWeight = 1 for non‑critical, 2 for critical

shortagePercent = ((min - rob) / min) * 100 (0 if min is 0 or missing)

daysBelowMinWeight = min(daysBelowMin, 30) or 0 if unknown

Query parameters (same as your draft, but without purchase fields):

Parameter	Type	Description

thresholdPercent	number	e.g. 50 = items at ≤ 50% of min
