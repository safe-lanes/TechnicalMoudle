We need a small but important UI enhancement in the Work Orders (W.O) module.

Requirement
In the Planned tab of the Work Orders list, add a new column “Planned Date” in the table, immediately after the “Due Date” column.

Column order (left to right) should become:
… | Due Date | Planned Date | Status | Actions (maintain existing columns before Due Date as they are). 

This column should show the planned execution date that is set from the Work Order Planner screen for that specific work order.

Behavior details
Data source

Use the same field that the Planner uses for the “Planned Date” input in the Work Order Planner screen.

For each WO row in the Planned tab:

If a planned date has been set in Planner → show that date in Planned Date.

If no planned date exists → show — (dash) or keep the cell blank, consistent with how empty Due Date is shown currently.

Scope

This new column is required only in the Planned tab grid.

Do not add it to Due, Overdue, Pending Approval, Completed tabs for now (unless it is trivial to reuse and does not clutter; but the requirement is specifically for Planned).

Column formatting

Use the same date display format as the existing Due Date column.

The column should be sortable by Planned Date if current grid supports column sorting.

Width should be similar to Due Date column.

Planner integration

When a user opens Planner for a vessel and updates planned dates for one or more work orders:

after saving and returning to Work Orders → the Planned tab should show updated Planned Date values without data mismatch.

If the Work Orders list is already open while user changes dates in Planner (same session), ensure the list is refreshed or re-fetched so that Planned Date values reflect the latest saved data.

Filtering / search

Existing filters (Vessel, Period, All Ranks, Criticality, search box) should continue to work as they do now.

No new filtering logic is required for Planned Date in this task.

Empty state

If no work orders exist in Planned tab, table should behave as before; Planned Date column simply remains empty.

Implementation notes
Identify the field in your API/DTO that represents the planner’s planned execution date (often named something like plannedExecutionDate / planned_date).

Ensure the Work Orders API response used by the Planned tab includes that field.

Extend the table column configuration for the Planned tab to include this new column and map it to that field.

Out of scope
No changes to how planned dates are selected or saved inside Planner.

No changes to due date or status calculation logic.

No changes to other tabs or modules.

Final expectation
After this change:

In the Planned tab, users will see both:

Due Date – when the system says the job is due.

Planned Date – when the job is actually scheduled in Planner.

This will help them quickly see which planned jobs have dates assigned and which still need scheduling, without opening Planner for every case.
