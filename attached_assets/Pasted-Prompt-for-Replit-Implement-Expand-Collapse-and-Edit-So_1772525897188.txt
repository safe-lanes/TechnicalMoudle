Prompt for Replit – Implement Expand, Collapse, and Edit (Sort Order) in Component Section

Objective

Replicate the Expand, Collapse, and Edit functionality from the Fleet Component section into the Component section (as shown in the 2nd image). The behavior and hierarchy handling must match the Fleet Component module.

1. UI Enhancement

Add the following controls in the Component section (aligned similar to Fleet Component):

Expand

Collapse

Edit

Maintain consistent icons, styling, spacing, and tree indentation format.

2. Functional Requirements
A. Expand Functionality (Node-Level Only)

When a user selects a specific Component Code and clicks Expand:

Only the immediate child components under that selected parent must be expanded.

Other parent nodes must remain unchanged.

Expansion must be limited strictly to the selected node (not global expand).

Support multi-level hierarchy (Parent → Child → Sub-child).

Data should load dynamically without full page refresh.

B. Collapse Functionality (Node-Level Only)

When a user selects a specific Component Code and clicks Collapse:

Only the child components under that selected parent must collapse.

Other expanded nodes elsewhere in the tree must remain unaffected.

Nested child levels under that node must also collapse.

C. Edit Functionality (Tree Sort Order Management)

The Edit button in this section is specifically for:

Changing the Sort Order of Component Codes in Tree View

Enable functionality similar to drag-and-drop reordering within the same hierarchy level.

User should be able to:

Change the sequence/order of components under the same parent.

Reorder sibling components visually in the tree view.

Logic Requirements:

Sorting must apply only within the same parent group.

Parent-child relationship must not change unless explicitly allowed.

Update the corresponding sort_order (or equivalent column) in the Component table.

Changes must reflect immediately in the UI after saving.

No full page reload.

3. Backend Requirements

Use existing parent-child relationship field (e.g., parent_component_code).

Introduce or use existing sort_order column for ordering logic.

Ensure:

Referential integrity is maintained.

No unintended hierarchy changes occur.

Validation prevents movement outside permitted scope.

4. Validation & Safeguards

Prevent drag/drop across different parent groups (unless future requirement).

Ensure sort order updates are atomic and consistent.

Handle concurrent edits safely.

5. Expected Behavior

Expand/Collapse works strictly at selected node level.

No global tree expansion or collapse.

Edit enables drag-and-drop style reordering within same parent.

Sort order persists in database and reflects immediately.

Smooth UX with no page refresh.
