Replit Prompt — Fix Vessel-wise Handling in “Modify PMS – Change Requests”
Context

The UI currently shows data across all vessels
While saving a change request into the change_request table:
The system always saves vessel_id = 'V001'
This happens even when another vessel is selected
This breaks vessel-wise data isolation, which is a core PMS rule.
❌ Current Incorrect Behavior
Change Requests list shows all-vessel data
On save:
change_request.vessel_id is always set to 'V001'
Selected vessel context is ignored
Result:
Cross-vessel contamination
Incorrect reporting and approvals
✅ Expected Correct Behavior
Change Requests must be handled vessel-wise
On save:
change_request.vessel_id must be the currently selected vessel
All fetch, save, update, and approval flows must:
Respect vessel context consistently

Frontend

Missing from payload
Overwritten before API call
Backend
Where vessel_id is assigned during save
Whether:
A default value (V001) is hardcoded
A fallback is applied when vessel_id is undefined
API Contract
Whether vessel_id is:
Expected from frontend
Derived from session / token
Incorrectly defaulted
Replit must clearly explain why V001 is always used.

Ensure selected vessel ID is passed end-to-end

Hardcoded V001 fallback logic
