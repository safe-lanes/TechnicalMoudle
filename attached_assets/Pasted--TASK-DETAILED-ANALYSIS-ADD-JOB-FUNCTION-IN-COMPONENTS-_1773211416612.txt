 
TASK: DETAILED ANALYSIS – "+ADD JOB" FUNCTION IN COMPONENTS

Objective:

Perform a detailed analysis of the **"+Add Job" function in the Components section** to identify why the job data is not being saved and why an error appears during the save process.

Scope:

• Components Module  
• "+Add Job" Function

--------------------------------------------------

1. Functional Flow Analysis

Analyze how the **+Add Job function** currently works.

Verify:

• How the "+Add Job" form is triggered from the Component screen  
• What fields are captured in the job creation form  
• What frontend action is triggered when clicking Save  
• Which backend API/service handles the job creation request

--------------------------------------------------

2. Error Investigation

When attempting to save the job:

• The system shows an error and the data is not saved.

Investigate:

• What exact error message is generated
• Whether the API request is failing
• Whether any validation rule is blocking the save
• Whether required fields are missing in the request payload

--------------------------------------------------

3. Data Saving Verification

Confirm whether the job data is being saved or not.

Check:

• Which database table should store job records (e.g., jobs table)
• Whether the INSERT query is triggered
• Whether any transaction rollback is happening

Verify whether the data is partially saved or not saved at all.

--------------------------------------------------

4. Vessel Concept Validation

Check whether the **+Add Job function follows the Vessel Concept**.

Verify:

• Whether the selected vessel ID is passed during job creation
• Whether the job is linked to both:

  component_id  
  vessel_id

• Whether the backend logic requires vessel_id but it is missing from the request.

--------------------------------------------------

5. Root Cause Identification

Identify the exact cause of the save failure, such as:

• API request failure  
• Missing vessel_id  
• Missing component_id  
• Validation error  
• Incorrect database mapping  
• Backend service not triggering the insert query  
• Foreign key constraint failure

--------------------------------------------------

6. Correct Saving Logic

The correct job creation process must ensure:

• Job is linked to the selected component  
• Job is linked to the selected vessel  

Example structure:

INSERT INTO jobs (
    vessel_id,
    component_id,
    job_code,
    job_title,
    maintenance_type,
    frequency_value,
    frequency_unit,
    is_active
)
VALUES (
    selected_vessel_id,
    selected_component_id,
    job_code_value,
    job_title_value,
    maintenance_type_value,
    frequency_value,
    frequency_unit,
    'Yes'
);

--------------------------------------------------

7. Corrective Implementation Plan

Prepare a corrective plan including:

• Fixing the API request payload
• Ensuring vessel_id is included
• Ensuring component_id is passed correctly
• Fixing validation rules if blocking save
• Correcting database insert logic
• Ensuring job creation follows vessel-based architecture

--------------------------------------------------

8. Testing After Fix

After implementing corrections perform validation tests:

Test 1  
Add a new job to a component and verify successful save.

Test 2  
Confirm the job record appears in the job list.

Test 3  
Verify the job is linked to the correct component and vessel.

Test 4  
Verify no errors appear during save.

--------------------------------------------------

Expected Result

• +Add Job function successfully saves job records
• Job records are stored in the correct database table
• Jobs are linked to the selected component and vessel
• Save errors are resolved
