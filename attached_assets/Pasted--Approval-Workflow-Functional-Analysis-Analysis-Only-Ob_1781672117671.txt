# Approval Workflow – Functional Analysis (Analysis Only)

## Objective

Analyze the attached Approval Workflow requirements and understand the complete business flow before implementation.

The Approval Workflow page allows administrators to configure approval levels for various PMS and Defect-related transactions. Based on the configuration, requests raised from the Vessel shall be routed to the appropriate approver(s) before the approved changes are synchronized back to the Vessel.

This task is strictly for functional analysis. Do not perform any development or implementation.

# Approval Configuration Logic

For every configurable item, the user can select:

### Level 1

Only Level 1 approval is required.

### Level 2

Only Level 2 approval is required.

### Level 1 + Level 2

Approval must pass through Level 1 first and then Level 2.

---

# Business Flow Analysis

## Scenario 1 – Only Level 1 Selected

### Expected Flow

1. Vessel user raises a request.
2. System identifies the request category.
3. System checks Approval Workflow configuration.
4. Level 1 is enabled.
5. Request is routed to the Level 1 Approver.
6. Level 1 Approver reviews the request.
7. Upon approval:

   * Request status changes to Approved.
   * Requested changes are processed.
   * Synchronization record is generated.
8. Changes become available during Vessel synchronization.

### Workflow

Vessel User → Request Submission → Level 1 Approval → Synchronization → Vessel

---

## Scenario 2 – Only Level 2 Selected

### Expected Flow

1. Vessel user raises a request.
2. System identifies the request category.
3. System checks Approval Workflow configuration.
4. Level 2 is enabled.
5. Request bypasses Level 1.
6. Request is routed directly to Level 2 Approver.
7. Level 2 Approver reviews the request.
8. Upon approval:

   * Request status changes to Approved.
   * Requested changes are processed.
   * Synchronization record is generated.
9. Changes become available during Vessel synchronization.

### Workflow

Vessel User → Request Submission → Level 2 Approval → Synchronization → Vessel

---

## Scenario 3 – Both Level 1 and Level 2 Selected

### Expected Flow

1. Vessel user raises a request.
2. System identifies the request category.
3. System checks Approval Workflow configuration.
4. Both Level 1 and Level 2 are enabled.
5. Request is routed to Level 1 Approver.
6. Level 1 reviews the request.
7. Upon approval:

   * Request status changes to Pending Level 2 Approval.
8. Request is forwarded to Level 2 Approver.
9. Level 2 reviews the request.
10. Upon approval:

    * Request status changes to Approved.
    * Requested changes are processed.
    * Synchronization record is generated.
11. Changes become available during Vessel synchronization.

### Workflow

Vessel User → Request Submission → Level 1 Approval → Level 2 Approval → Synchronization → Vessel

# Rejection Analysis

## Level 1 Rejection

If Level 1 rejects the request:

* Workflow terminates immediately.
* Request status changes to Rejected.
* Request should not move to Level 2.
* No synchronization should occur.
* Vessel user should be able to view rejection remarks.

### Workflow

Vessel User → Level 1 Rejection → Workflow Closed

---

## Level 2 Rejection

If Level 2 rejects the request:

* Workflow terminates immediately.
* Request status changes to Rejected.
* No synchronization should occur.
* Vessel user should be able to view rejection remarks.

### Workflow

Vessel User → Level 1 Approval → Level 2 Rejection → Workflow Closed

---

# Status Flow Analysis

Suggested workflow statuses:

### Request Raised

Initial status when Vessel user submits request.

### Pending Level 1 Approval

Waiting for Level 1 review.

### Pending Level 2 Approval

Waiting for Level 2 review.

### Approved

All configured approvals completed.

### Rejected

Request rejected by any approval level.

### Synchronized

Approved request successfully synchronized to Vessel.

---

# Synchronization Analysis

Synchronization should occur only after all configured approval levels have completed approval.

The system should never synchronize:

* Pending requests
* Rejected requests
* Partially approved requests

Synchronization should occur only when:

* Request Status = Approved
