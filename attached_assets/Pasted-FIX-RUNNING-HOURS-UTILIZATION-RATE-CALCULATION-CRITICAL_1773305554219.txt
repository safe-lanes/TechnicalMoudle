FIX RUNNING HOURS UTILIZATION RATE CALCULATION (CRITICAL CORRECTION)

PROBLEM IDENTIFIED:

The current utilization rate calculation is fundamentally incorrect for a maritime Planned Maintenance System.

Current Implementation (WRONG):

text
utilizationRate = (Sum of positive RH deltas in audit trail during period / Period hours) × 100
Why this is wrong:

Depends on update frequency, not actual usage

If crew doesn't update RH daily → Shows 0% even if machinery is running

Measures "data entry activity" instead of "machinery utilization"

Useless for operations: A generator running 24/7 shows 0% if RH hasn't been updated recently

Example of the problem:

S-Band Radar last updated: 25-Jan-2026 (RH: 100 hrs)

Today: 12-Mar-2026 (still showing RH: 100 hrs because no updates)

Reality: Machinery might be running constantly

Current system shows: 0.0% utilization ❌ (because no audit entries in last 7 days)

What it SHOULD show: Calculation based on actual RH change from period start

CORRECT IMPLEMENTATION FOR MARITIME PMS:

Formula:
text
utilizationRate = min(((CurrentRH - RHatPeriodStart) / MaxPossibleHours) × 100, 100.0)

Where:
- CurrentRH = Latest running hours value for the component (from components table)
- RHatPeriodStart = Running hours value at the start of the selected period
- MaxPossibleHours = Period days × 24 hrs/day
Key Difference:
Aspect	Current (WRONG)	Correct (MARITIME PMS)
What it measures	RH updates logged in audit trail	Actual machinery usage
Data source	running_hours_audit entries in period	Cumulative RH values (current vs period start)
If no updates	Shows 0%	Shows actual utilization based on RH difference
Use case	Software activity tracking	Machinery operation tracking

// NEW APPROACH - Calculate utilization based on actual RH change

async function calculateUtilizationRate(component, period) {
  // 1. Get current RH from component
  const currentRH = component.currentCumulativeRH || 0;
  
  // 2. Calculate period start date (rolling window)
  const now = new Date();
  const periodHours = PERIOD_HOURS_MAP[period]; // 168 for weekly, etc.
  const periodStartDate = new Date(now.getTime() - (periodHours * 60 * 60 * 1000));
  
  // 3. Get RH at period start from audit trail
  const historicalRHEntry = await storage.getRunningHoursAtDate(
    component.id, 
    periodStartDate
  );
  
  // If no historical data, use oldest available or 0
  const rhAtPeriodStart = historicalRHEntry?.runningHours || 0;
  
  // 4. Calculate RH increase during period
  const rhIncrease = currentRH - rhAtPeriodStart;
  
  // 5. Handle edge cases
  if (rhIncrease < 0) {
    // RH decreased (meter reset/replacement) - show 0% or N/A
    return { rate: 0, warning: 'RH_DECREASED' };
  }
  
  // 6. Calculate utilization rate
  const maxPossibleHours = periodHours; // Already in hours (168, 720, etc.)
  let utilizationRate = (rhIncrease / maxPossibleHours) * 100;
  
  // 7. Cap at 100% (data quality check)
  if (utilizationRate > 100) {
    console.warn(`Utilization >100% for ${component.name}: ${utilizationRate}% (${rhIncrease} hrs in ${maxPossibleHours} hrs)`);
    utilizationRate = 100;
  }
  
  // 8. Round to 1 decimal
  utilizationRate = Math.round(utilizationRate * 10) / 10;
  
  return {
    rate: utilizationRate,
    details: {
      currentRH,
      rhAtPeriodStart,
      rhIncrease,
      periodDays: periodHours / 24,
      maxPossibleHours: periodHours,
      periodStartDate: periodStartDate.toISOString(),
      periodEndDate: now.toISOString()
    }
  };
}
3. Add New Storage Method
File: server/postgresStorage.ts

Add this method to get RH at a specific date:

typescript
async getRunningHoursAtDate(
  componentId: string, 
  targetDate: Date
): Promise<{ runningHours: number; enteredAtUTC: Date } | null> {
  // Get the closest RH entry at or before the target date
  const result = await this.db
    .select({
      runningHours: runningHoursAudit.newRh,
      enteredAtUTC: runningHoursAudit.enteredAtUtc
    })
    .from(runningHoursAudit)
    .where(
      and(
        eq(runningHoursAudit.componentId, componentId),
        lte(runningHoursAudit.enteredAtUtc, targetDate)
      )
    )
    .orderBy(desc(runningHoursAudit.enteredAtUtc))
    .limit(1);
  
  if (result.length === 0) {
    // No historical data - return null or oldest available
    // Alternatively, return the component's initial RH (usually 0)
    return null;
  }
  
  return {
    runningHours: parseFloat(result[0].runningHours),
    enteredAtUTC: result[0].enteredAtUTC
  };
}
