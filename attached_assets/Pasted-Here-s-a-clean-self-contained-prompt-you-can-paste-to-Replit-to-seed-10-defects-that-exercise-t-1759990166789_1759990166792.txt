## 🚀 Task: Seed 10 defects to validate **Recurring Defects** (with persistence)

### Objectives

1. **Create 10 defects** in the defects table using persistent storage.
2. Ensure **at least 5 defects share the same equipment key** (same `equipmentCategory + type + make + model`) so they appear under **Recurring Defects**.
3. Mix of:

   * Same equipment across **different vessels** and **same vessel**.
   * Open/Closed statuses.
   * A couple with **CoC = true** to validate the CoC filter.
4. Confirm they render under:

   * **Defects › Active** (open)
   * **Defects › Resolved** (closed)
   * **Sidebar › Recurring Defects** (grouped by equipment key)
   * **Sidebar › CoC** (only CoC=true)
5. Use **idempotent seeding** (upsert by `seedId`) so re-running does not duplicate.

### Data model rules to follow (same as earlier Q&A)

* Vessels: upsert by **name**; create if not found, return `vesselId`.
* Dates: store **ISO (`YYYY-MM-DD`)**; UI can format to `DD-MM-YYYY`.
* Status: store lowercase `'open' | 'closed'`; UI can title-case.
* Equipment key (for recurring):
  `equipment_key = normalize(category|type|make|model)` (lowercase, trimmed, collapse spaces).
* Defaults if missing:
  `severity="2 - Minor"`, `priority="Medium"`, `occurrenceType="Routine"`, `operationCondition="Sailing"`, `isCoC=false`.
* Add `seedId` (unique) to each seeded defect and **upsert on seedId**.
