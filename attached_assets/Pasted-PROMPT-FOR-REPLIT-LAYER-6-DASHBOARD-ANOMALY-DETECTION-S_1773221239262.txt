2. BACKEND API ENDPOINTS:

Create the following API endpoints:

A. GET /api/pms/anomalies/dashboard

Purpose: Fetch all active anomalies for dashboard display

Query Parameters:

status (optional): Filter by status (PENDING_REVIEW, ACKNOWLEDGED, etc.)

severity (optional): Filter by severity (HIGH, MEDIUM, LOW)

limit (optional): Number of records to return (default: 10)

dateFrom (optional): Filter anomalies detected from this date

dateTo (optional): Filter anomalies detected until this date

Response: Array of anomaly objects sorted by severity (HIGH first) then by detectedAt (newest first)

Access: Available to Superintendent and Chief Engineer roles only

B. POST /api/pms/anomalies/detect

Purpose: Triggered automatically when a work order is completed

Logic:

Check for backdating (Part A flag from Layer 1)

Check for missed cycles (Part B badge from Layer 2)

Check for suspicious patterns (analyze last 30 days of completions for same component)

Calculate severity:

HIGH: missedCycles >= 3 OR daysLate >= 21 OR backdating >= 7 days

MEDIUM: missedCycles >= 2 OR daysLate >= 14 OR backdating >= 3 days

LOW: missedCycles == 1 OR daysLate >= 7 OR backdating >= 1 day

Create anomaly record in workOrderAnomalies collection

Send notification to Superintendent (integrate with existing notification system)

C. GET /api/pms/anomalies/statistics

Purpose: Get summary statistics for dashboard tile header

Response:

javascript
{
  totalPending: Number,
  totalHigh: Number,
  totalMedium: Number,
  totalLow: Number,
  lastDetected: Date,
  trendPercentage: Number  // Increase/decrease vs last month
}
D. PATCH /api/pms/anomalies/:anomalyId/acknowledge

Purpose: Mark anomaly as acknowledged by Superintendent

Request Body:

javascript
{
  acknowledgedBy: String,
  notes: String  // Optional
}

4. AUTOMATIC ANOMALY DETECTION INTEGRATION:

Where to integrate detection logic:

In your existing work order completion flow (likely in workOrderController.js or similar), ADD the anomaly detection call AFTER successful completion:

javascript
// Pseudo-code location
async function completeWorkOrder(workOrderId, completionData) {
  // ... existing completion logic ...
  
  // Save completion data
  await workOrder.save();
  
  // NEW: Trigger anomaly detection
  await detectAndLogAnomalies(workOrder, completionData);
  
  // ... rest of existing logic (notifications, etc.) ...
}
Anomaly Detection Logic (detectAndLogAnomalies function):

javascript
1. Extract completion date, due date, frequency from work order
2. Calculate:
   - daysLate = completionDate - dueDate
   - missedCycles = get from Part B calculation (already implemented in Layer 2)
   - isBackdated = check if Part A flag exists (already implemented in Layer 1)

3. Check for suspicious patterns:
   - Query last 5 completions of same component/job in last 30 days
   - If 3+ completions have backdating: Flag as "SUSPICIOUS_PATTERN"
   - If consecutive completions show increasing delay: Flag pattern

4. Determine anomaly types:
   - If isBackdated: Add "BACKDATING" to types
   - If missedCycles > 0: Add "MISSED_CYCLES" to types  
   - If pattern detected: Add "SUSPICIOUS_PATTERN" to types

5. If any anomaly type exists:
   - Calculate severity (HIGH/MEDIUM/LOW as per rules above)
   - Create anomaly record in database
   - Send notification to Superintendent
   - Return anomaly object

6. If no anomalies: Return null (no action needed)
