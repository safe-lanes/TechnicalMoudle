We need to update how the UI determines the current user role, but this change must only be done in the frontend logic.
⚠️ Important constraints:
NO database changes
NO backend changes
NO schema changes
NO API changes
ONLY adjust how the UI determines the role
The application already has role-based UI logic, so we must reuse the existing role system.
Context
The UI currently contains a role dropdown switcher used during development to manually simulate roles:
Sail Admin
Client Admin
Head of Dept
Vessel
This dropdown was only used for testing UI behavior.
Now the UI must automatically determine the role from the logged-in user.
However:
In the real application
User data will come from localStorage:
localStorage.userType
localStorage.userProfile
Example:
userType = "Office" | "Ship"
userProfile = {
   role: "Sail Admin" | "Super Admin" | "Vessel Admin" | "Vessel User"
}
Replit Environment Limitation
Replit does not have the actual login system, therefore:
localStorage.userType does not exist
localStorage.userProfile does not exist
Instead, Replit already provides a mock logged-in user object:
currentUser
Example structure:
currentUser = {
   role: string
}
So in Replit the UI must derive the role from currentUser.role.
Required Change
Update the frontend role detection logic so that it works like this:
Step 1 — Try localStorage first
If these keys exist:
localStorage.userType
localStorage.userProfile
then determine the UI role from them.
Step 2 — Replit fallback
If those keys do not exist, assume the application is running in Replit development mode and use:
currentUser.role
to determine which UI should be rendered.
Role Mapping (Keep Existing UI Roles)
Do NOT rename existing UI roles.
Map the logged user role to the existing UI roles.
Logged Role	UI Role
Sail Admin	Sail Admin
Super Admin	Client Admin
Vessel Admin	Head Of Dept
Vessel User	Vessel
Example:
if (currentUser.role === "Super Admin") {
   activeRole = "Client Admin"
}
Important Rules
Do NOT:
change database tables
create new roles
modify APIs
modify backend authentication
rebuild the role system
Only adjust how the frontend decides which role is active.
The goal is simply:
Logged user role
        ↓
Mapped UI role
        ↓
Existing UI permission logic
Final Goal
The UI should render the correct role-based interface automatically using:
localStorage.userType
+
localStorage.userProfile.role
and in Replit mode it must fallback to:
currentUser.role
This allows the UI to work correctly without requiring a real login system inside Replit.
