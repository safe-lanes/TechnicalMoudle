Component Tree
The tree has 8 fixed root categories (Ship General, Hull, Equipment for Cargo, etc.)
All child components are loaded from the database and nested under these roots based on parentId
The tree builds itself by matching each component's parentId to its parent's componentCode
Components are sorted by code numerically at each level
Clicking a tree node expands/collapses it and selects the component to show its details in the right panel
Add Component
Triggered by clicking "Add" button (usually on a parent node in the tree)
Opens AddEditComponentForm modal in add mode (isEditMode = false)
Pre-fills the parent component code if adding under an existing component
Component Category is auto-derived from the component code's first digit
On save: POSTs to /api/components, invalidates query cache, tree refreshes with new component
Edit Component
Triggered by clicking "Edit" on an existing component
Opens AddEditComponentForm modal in edit mode (isEditMode = true)
Fetches existing component data and populates all fields
Shows all 8 sections (A-H) with related data (jobs, spares, history, etc.)
On save: PATCHes to /api/components/{id}, cache invalidates, UI updates
Section B - Running Hours & Condition Monitoring
Displays the component's running hours counter and related data
Has 3 counter types:
MASTER: This component owns its own RH counter (self-tracked)
INHERITED: Uses RH from a parent/master component
NONE: Not an RH-driven component
Auto-detects type from jobs: if component has jobs with "Running Hours" frequency, it's treated as MASTER
Shows: Current RH, Last Updated date, Counter Source
For INHERITED type, fetches the master component's RH value
Section C - Jobs
Lists all jobs assigned to the selected component and its children (recursive)
Each job row shows: Job Code, Title, Task Type, Frequency, Last Done, Next Due, Generate WO button
Add Job button: Navigates to /pms/work-order/new/{componentCode}?mode=template
Clicking a job row navigates to the job form page
Add Job Button Flow
User clicks "Add Job" in Section C
Navigates to work order form page in template mode
Component code is pre-filled from the URL
User fills job details (title, frequency type, interval, task type, etc.)
On save: POSTs to /api/jobs, job appears in component's job list
Job Form
Located at /pms/job/{jobId} or /pms/work-order/new/{componentCode}
Has multiple sections for job configuration
Key fields: Job Code, Job Title, Component, Task Type, Frequency (Calendar vs Running Hours), Interval
For RH-based jobs: tracks intervalRunningHour, calculates remaining RH until due
"Generate WO" creates an actual work order from the job template
