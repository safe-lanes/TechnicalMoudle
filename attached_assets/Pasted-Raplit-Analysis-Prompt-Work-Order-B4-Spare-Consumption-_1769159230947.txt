Context
In the Work Order (WO) → B4. Spare Parts Consumed section:
User selects a Spare
Selects a Location (Location A or Location B)
Enters Qty Used
Closes / completes the Work Order
❌ Current Observed Behavior
Currently, when Qty Used is entered and the WO is closed:
The system directly reduces the total ROB in the spares.rob column
The reduction does not first apply to the selected location
Location-wise ROB (rob_location_a / rob_location_b) is bypassed or not respected
This leads to:
Incorrect location-wise stock
Inventory inconsistency
Misalignment with physical spare storage
✅ Correct Business Logic (Expected)
Spare consumption must always be location-driven first.
Important Design Constraint (Must Be Respected)
In the Spares table, there are ONLY TWO locations:
Location A
Location B
These are fixed and permanent
No new locations will be created in the future
Location meaning is defined as:
location → text label for Location A
location_2 → text label for Location B
🔁 Correct Consumption Flow (Reference Rule)
When a WO is closed and spares are consumed from B4:
User selects:
Spare
Location (A or B)
Qty Used
System must:
Reduce ROB ONLY for the selected location:
If Location A → reduce spares.rob_location_a
If Location B → reduce spares.rob_location_b
Total ROB (spares.rob) must then reflect the location reduction
Total ROB should be derived from location values
It must not be reduced independently
