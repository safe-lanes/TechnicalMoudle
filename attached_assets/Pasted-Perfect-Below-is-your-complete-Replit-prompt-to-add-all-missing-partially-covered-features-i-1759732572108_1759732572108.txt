## 🎯 PURPOSE:

To capture complete operational and accountability details for each defect, we need to add the following new fields and rename one existing label. These updates improve traceability, Root Cause Analysis (RCA), and reporting accuracy.

---

## 1️⃣ FIELD: **Raised By (Who Raised the Defect)**

### Function:

Identify which crew member officially logged/reported the defect.

### UI Placement:

* Add this field in the **top Basic section**, below or beside “Defect ID”.
* Label: `Raised By`
* Type: Dropdown
* Placeholder: `Select reporting crew member`
* Auto-fill with **current logged-in user**, but allow override.
* Dropdown List Format: `Rank - Name`
  Example:

  * Chief Engineer – John Mathews
  * 2nd Officer – Rahul Verma
  * AB – Suresh Kumar
* Tooltip: “Auto-selected from login. Change if reporting on behalf of another crew member.”
* Validation: Required field (must not be blank).

### Data Source:

Fetch list dynamically from ship’s **Crew Directory** table or crew API.

### Backend Mapping:

```json
{
  "raisedById": "uuid",
  "raisedByName": "John Mathews",
  "raisedByRank": "Chief Engineer"
}
```

## 2️⃣ FIELD: **Operating Condition / Location**

### Function:

Capture where the vessel was when the defect occurred (important for cause analysis).

### UI Placement:

* Add directly below “Raised By” field in the **Basic Details** section.

### Layout:

**Label:** `Operation Condition / Location`

* Radio Buttons (horizontal layout):

  * Sailing 🚢
  * Port 🏗️
  * At Anchor ⚓
* Next to radio group, add **textbox** labeled `Location / Port Name`

  * Placeholder: `Enter port or position (e.g. Mumbai Anchorage or Lat/Long)`
  * Required only if “Port” or “Anchor” is selected

### Validation:

* Must select one of the three options.
* Textbox optional for “Sailing” but required for “Port” or “Anchor”.

### Tooltip:

“Select vessel condition during occurrence and specify port/position if applicable.”

### Backend Mapping:

```json
{
  "operatingCondition": "PORT",     // Values: SAILING | PORT | ANCHOR
  "locationText": "Singapore Anchorage"
}
```

## 3️⃣ FIELD: **Routine / Breakdown**

### Function:

Differentiate between planned/routine issues and unexpected failures.

### UI Placement:

Below “Operation Condition” in Basic section.

* Label: `Occurrence Type`
* Type: Toggle or radio buttons

  * Routine
  * Breakdown
* Default Value: Routine
* Validation: Required
* Tooltip: “Mark as Breakdown for unplanned equipment failures.”

### Backend Mapping:

```json

```

## 6️⃣ FIELD: **Deferment Procedure**

### Function:

Allow user to defer defect rectification with proper reason.

### UI Placement:

Below Target Date for Closure.

* Toggle: `Deferment Needed? (Yes/No)`
* If “Yes” is selected → Show:

  * Textbox: “Deferment Reason” (required)
  * Date Picker: “Proposed New Target Date” (required)
  * Checkbox: “Approval Required” (default checked)
* Add a yellow “Deferred” badge in the log table row once approved.

### Validation:

* Deferment Reason & New Date required if toggle = Yes.

### Backend Mapping:

```json
{
  "isDeferred": true,
  "deferReason": "Awaiting spare part delivery",
  "deferNewTargetDate": "2025-12-10",
  "deferApprovalRequired": true
}
```
