Question 1 — current_cumulative_rh: Total or Current Meter Only?
Right now, current_cumulative_rh stores only the current meter reading (e.g. 500 hrs after replacement), while the pre-replacement accumulated total (e.g. 4,000 hrs) sits separately in meter_replaced_last_rh. The displayed total is 4,500 hrs.
Question: Should current_cumulative_rh be changed to always store the full lifetime total (4,500 hrs) so the grid can read it directly — or should the two-column split (rh_current_master + meter_replaced_last_rh) be kept and the requirement be considered satisfied since the computed result is always the same number?

Question 3 — updateChildRH: Which Date Goes Into last_updated?
When a user manually edits a child (INHERITED) component's RH and types a past date (e.g. "10-Jan-2026"), there are two possible values:
•	The user's entered reading date (10-Jan-2026)
•	The server time when the edit was saved (today)
Question: Should components.last_updated store the user's entered reading date (10-Jan-2026) — consistent with how MASTER updates work — or is the server insertion time acceptable for child component edits?
Answer: It has to save the user entered value

Question: Is the running_hours_audit read for utilisation calculations out of scope for this requirement — meaning the requirement applies only to the current RH value and last-updated date display, not to historical/period calculations?
