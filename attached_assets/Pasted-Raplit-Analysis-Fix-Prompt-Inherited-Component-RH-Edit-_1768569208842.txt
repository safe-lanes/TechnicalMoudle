Raplit Analysis & Fix Prompt — Inherited Component RH Edit Error & Scope Issue
Context
In the Inherited Components – Running Hours screen, users can edit the RH value of an inherited component using the pencil (edit) icon.
Currently:
An unexpected error popup appears when editing inherited RH
The behavior does not fully match the intended inherited RH design
There is a risk that RH changes may reflect for all inherited components, which is not desired in this case
Shape
❌ Current Incorrect Behavior
User opens Inherited Components RH popup
Clicks Edit (pencil icon) for a specific inherited component
Enters a new RH value
On save:
An error popup appears, and/or
RH update impacts more than the selected inherited component
This is incorrect because:
Inherited component RH edit is allowed
RH = 0 popup is not applicable for inherited components
The update must be scoped only to the selected inherited component
Shape
✅ Expected Correct Behavior
When editing RH for an Inherited component:
No error popup should appear
RH = 0 validation popup must NOT apply
The RH update must:
Apply only to the selected inherited component
NOT automatically propagate to all inherited components
Other inherited components must remain unchanged
The behavior must be:
Isolated
Predictable
Consistent with historical / intended design
🔒 Mandatory Constraints (Very Strict)
DO NOT change any functionality
DO NOT change any core logic
DO NOT impact master RH calculation
DO NOT affect other inherited components
DO NOT change APIs or database schema
DO NOT impact any other PMS module
❗Fix must be applied only after explicit PROCEED command.
🧠 Analysis Required (Before Any Fix)
Raplit must analyse first and make NO changes, and explain:
1. Error Popup Trigger
Identify:
Where the popup is triggered
Which validation condition is firing
Confirm:
Why it is incorrectly applied to inherited components
2. RH Update Scope
Trace:
Current RH update flow when editing inherited RH
Confirm:
Whether the update is:
Writing to the master component
Broadcasting to all inherited components
Identify:
Why the update is not scoped to the selected component
3. Data Storage Clarification
Identify:
Which table and column store the edited RH value
Confirm:
Whether there is (or is not) a component-level RH override column
4. UI State & Binding
Analyse:
Whether the UI incorrectly treats inherited RH edits as master updates
Whether missing flags / conditions cause global propagation
🛠️ Fix Requirements (ONLY After PROCEED)
After approval, Raplit must:
Remove the error popup for inherited component RH edits
Ensure RH updates:
Apply only to the selected inherited component
Do not cascade to other inherited components
Keep:
Master RH logic unchanged
Existing non-inherited validations unchanged

❌ Master RH calculation logic
