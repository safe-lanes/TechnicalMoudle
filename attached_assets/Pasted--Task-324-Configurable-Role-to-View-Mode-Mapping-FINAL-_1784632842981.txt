## CHANGES FROM SUBMITTED PLAN (read this first)

1. **Identity columns = NATURAL KEYS, not uuids (critical).** The plan registered
   both tables ONE_WAY_SHORE_TO_SHIP with "uuid identity columns". Both tables are
   seeded by migration on BOTH sides (necessary — ships must never boot unmapped),
   so each side mints DIFFERENT uuids for the same logical rows. The one-way
   applier matches rows by `syncConfig.identityColumn`
   (`oneWayApplier.ts:160 — lookupColumn = identityCol || 'id'`): with a uuid
   identity, shore rows never match the ship's seeded rows and EVERY sync cycle
   inserts duplicates on ships. This is exactly the `approval_workflow_config`
   seeded-both-sides bug we fixed with natural-key convergence.
   **Fix:** `identityColumn: 'code'` for the view-modes master and
   `identityColumn: 'role_ruid'` for the mapping table. No applier change needed —
   unlike awc (whose identity was already a uuid, forcing the FORCE_COMPOSITE
   mechanism), here we simply declare the natural key AS the identity. Side
   effect (fine): on first sync the UPDATE brings shore's uuid onto the ship row,
   so uuids converge to shore's; the mapping references view modes by `code`, so
   nothing breaks while they converge.

2. **tsc baseline is 292, not 374.** 374 is the pre-merge fork number. New
   precondition before starting: `git fetch origin && git reset --hard
   origin/replit_dev` (converged tip) and confirm `npx tsc --noEmit` = 292 before
   any change; must still be ≤ 292 at commit.

3. **Migration numbers pinned: 139 (Drizzle table migration) + 140 (seed).**
   Current highest on origin/replit_dev is `138_repair_spare_location_stock_drift`.
   Check at build time (from REPLIT-FORK-GUIDELINES):
   `git fetch origin replit_dev && git ls-tree --name-only origin/replit_dev migrations/ | sort | tail -5`
   ⚠️ 139 is also earmarked by the Shipskart b2b link-tables design (designed,
   NOT committed). Whoever commits second renumbers — the runner is
   filename-keyed so this is hygiene, but check before both commits.

4. **The seed spec was under-specified — the real `mapLoggedRoleToUIRole` takes
   TWO inputs** (`userType`, `profileRole`) with DEFAULT-OPEN fallthroughs
   (verified in `shared/uiRoles.ts`). The seed must iterate `admn_role_master`
   active roles and compute `mapLoggedRoleToUIRole(roletype, assignedRole)` —
   `roletype` is the userType analogue ('Office'/'Ship'). The exact current
   behaviour (this IS the seed table):

   | roletype | assignedRole | mode |
   |---|---|---|
   | Office | Sail Admin | Sail_Admin |
   | Office | Admin | Tech_Superintendent |
   | Office | External 10 | External |
   | Office | anything else (incl. **Super Admin**, Client Admin, User, External 1-5, Offline Admin) | Client_Admin |
   | Ship | Vessel Admin, Vessel User 3 | Head_of_Dept |
   | Ship | anything else (Vessel Management, Vessel User, Vessel User 2/4, …) | Vessel |

   Note and preserve the oddity: **Super Admin seeds to Client_Admin** (that is
   today's behaviour; behaviour-neutral means keeping it — changing it is a
   product decision for Ghazi, not this task).
   **The ONE deliberate behaviour change to document loudly:** today unknown
   roles fall through OPEN (Office→Client_Admin, Ship→Vessel). After this task,
   a role created AFTER the seed is BLOCKED until an admin maps it. That is the
   point of the feature — say so in the delivery summary so support expects it.

5. **"Project-standard columns" corrected against migrations 136/137 as built.**
   For a ONE_WAY synced table the true REQUIREMENTS are: a stable identity column,
   **`is_deleted BOOLEAN DEFAULT FALSE`** (the provisioning exporter filters
   `COALESCE(is_deleted,false)=false` — its absence broke bundle generation in the
   137 build), and **`updated_at`** (the one-way gather keys on
   `updated_at > checkpoint`). The conventional extras (per
   `company_standard_grace_settings`, the closest template):
   `is_sync BOOLEAN DEFAULT FALSE` (snake_case in SQL; `isSync` only in Drizzle),
   `created_by_uuid` / `updated_by_uuid` TEXT, `created_at`,
   `updatedAt` via the `updatedAtColumn()` helper, `sort_order`. uuid columns use
   the house default `gen_random_uuid()::text`. Keep the uuids on both tables
   (`vmuuid`, `rvmuuid`) — they're just not the sync identity.
