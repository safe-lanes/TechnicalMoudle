Part 2: Fix export discrepancies
Now use that report audit to correct the exports.

The main rule is simple and non-negotiable:

PDF and Excel exports must be exact replicas of the report in view mode.
That means:

same visible columns,

same field order,

same logical structure,

same inclusion/exclusion of summary sections,

same report interpretation.

The export should not contain hidden columns, extra technical fields, or legacy standard column templates if those are not visible in the report view.

If the user cannot see a column in the report viewer, it should not suddenly appear in PDF or Excel. Exporting unseen columns is bad behavior and bad design.

Important UX rule
There is no sense in exporting something you cannot see. That is stupidity from a product standpoint. The report viewer is the source of truth. Exports must follow the viewer.

So for every report:

View mode is the canonical definition of the report.

PDF must match that definition.

Excel must match that definition.

No extra “standard columns” should be injected just because a generic export service exists.

No old legacy export templates should be used if they produce different output from the current view.

Make Excel export use the exact same visible report columns.
