Modify the authentication system so that no data is ever written to localStorage. The application should only read from localStorage. If data does not exist (as in the Replit environment), then the app should fallback to a static default user in memory only.
Current Problem
The app currently does the following on first load:
secureSetItem("userProfile", user);
secureSetItem("userRole", user.role);
secureSetItem("userType", derivedUIType);
secureSetItem("credentials", {
  sessionId: crypto.randomUUID(),
  createdAt: Date.now()
});
This writes values to encrypted localStorage.
This behavior must be completely removed.
Required Changes
1. Remove All LocalStorage Write Operations
Remove or delete any usage of:
secureSetItem(...)
localStorage.setItem(...)
Specifically remove these lines:
secureSetItem("userProfile", user);
secureSetItem("userRole", user.role);
secureSetItem("userType", derivedUIType);
secureSetItem("credentials", {
  sessionId: crypto.randomUUID(),
  createdAt: Date.now()
});
The application must never write anything to localStorage.
2. Allow LocalStorage Read Only
The app should only read values using:
secureGetItem(...)
localStorage.getItem(...)
Example:
const storedUser = secureGetItem("userProfile");
const storedRole = secureGetItem("userRole");
const storedType = secureGetItem("userType");
3. Use Static Default User When LocalStorage is Empty
If no user exists in localStorage, use this static in-memory user only.
const defaultUser = {
  id: "replit-default",
  name: "Munawer A. Modak",
  email: "munawer.modak@sail.com",
  role: "Office",
  userType: "Client_Admin"
};
Important rules:
This default user must NOT be written to localStorage
It must exist only in React state or context
It is used only when localStorage has no user
Example logic:
const storedUser = secureGetItem("userProfile");
if (storedUser) {
  setUser(storedUser);
} else {
  setUser(defaultUser);
}
4. Role Mapping Logic
System Role → UI Role mapping must stay the same:
Office → Client_Admin
Office → Sail_Admin
Office → Head_of_Dept
Vessel → Vessel
Default mapping when using fallback user:
userRole = "Office"
userType = "Client_Admin"
5. Role Switcher Should Continue Working
The role switcher in the top right of the UI must still allow switching between:
Client_Admin
Sail_Admin
Head_of_Dept
Vessel
However:
It should update React state only
It must NOT store anything in localStorage
Example:
setUserType(selectedRole);
6. Credentials Object Must Not Be Stored
Remove this logic completely:
secureSetItem("credentials", {
  sessionId: crypto.randomUUID(),
  createdAt: Date.now()
});
Credentials must exist only in memory if needed.
7. Final Expected Behaviour
Case 1 — Real Login System
If localStorage contains:
userProfile
userRole
userType
Then the app uses them.
Case 2 — Replit / Demo Mode
If nothing exists in localStorage:
The app automatically uses:
User: Munawer A. Modak
System Role: Office
UI Role: Client_Admin
But nothing is written to localStorage.
8. Summary
Implement the following rules:
 
Feature	Behavior
LocalStorage Write	❌ Disabled
LocalStorage Read	✔ Allowed
Default User	✔ In Memory Only
Role Switcher	✔ State Only
Credentials Storage	❌ Disabled
