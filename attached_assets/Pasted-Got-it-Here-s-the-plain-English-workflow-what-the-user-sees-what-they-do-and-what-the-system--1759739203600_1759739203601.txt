Got it. Here’s the **plain-English workflow**—what the user sees, what they do, and what the system does. No tech talk.

---

## 1) Where it all starts – the Defects screen

* The page has two lists: **Active** (open items) and **Resolved** (closed items).
* You can filter by period, vessel, fleet, search text, type, and due/overdue.
* Each row shows the main details and 5 action buttons: **View**, **Edit**, **Add Note**, **Link**, **Complete/Close**.

---

## 2) Creating a new defect (New Defect)

1. User clicks **New Defect**.
2. A **Defect Report form** opens. It has three tidy columns:

   * **Basic**: Vessel, Source, Defect Category, Defect Type, **Raised By** (rank & name), **Operation condition/location** (Sailing / Port / At Anchor + location text when relevant), **Occurrence type** (Routine / Breakdown).
   * **Equipment/Hardware**: Category, Type, Make, Model.
   * **Dates & Responsibility**: Date Issued, **Target Date for Closure**, Responsible Role (e.g., Chief Engineer), Date Completed (left empty on creation).
3. Below that:

   * **Description** – what happened.
   * **Standards (optional)** – Severity, VIQ version & ref, SFI ref.
   * **Cause Analysis**

     * **Immediate Cause** → click **Select** to open a checklist for **Unsafe Acts** and **Unsafe Conditions**. After choosing, the form shows a clean summary like:
       **Unsafe Acts:** A, B • **Unsafe Conditions:** C, D
     * **Root Cause** → click **Select** to open a checklist for **Individual Factors** and **System Factors**. After choosing, the form shows:
       **Individual Factors:** … • **System Factors:** …
     * Text boxes for “Further Explanation” are available under both sections.
4. User clicks **Save**.
5. The defect is created as **Open** and appears in the **Active** list. The list refreshes so the new row is visible.

---

## 3) What each action button does (on the list)

### A) View (eye)

* Opens a read-only view of the report showing everything that was filled, the selected causes, any notes, links, and files.
* Close the view to go back to the list.

### B) Edit (pencil)

* Opens the same form with all fields pre-filled.
* User updates what’s needed and **Save**.
* The list refreshes so the updated details show.

### C) Add Note (paperclip)

* Opens a small pop-up: a comment box, with optional file upload (photo, doc).
* On **Save**, the note (and any file) is added to the defect’s history.
* The list stays where it is; a success message confirms it.

### D) Link (chain)

* Opens a small pop-up to add a cross-reference (e.g., PO number, job, document, or URL).
* On **Save**, the link is stored with the defect.
* The list stays where it is; a success message confirms it.

### E) Complete / Close (check mark)

* Opens a pop-up to **finish** the defect:

  * **Closure comment** (required) – what was done and why it’s solved.
  * **Closure files** (optional) – photos/reports as evidence.
  * **Date completed** (defaults to today; can change).
* On **Submit**, the defect is marked **Closed**, disappears from **Active**, and will show under **Resolved**.

---

## 4) Resolved list

* Shows closed defects.
* You can still **View**, **Add Note**, and **Link**.
* Editing and closing are usually disabled unless you later decide to allow reopen (not part of this basic flow).

---

## 5) Basic rules the system enforces

* You must select: Vessel, Source, Defect Category, Defect Type, Date Issued, **Target Date for Closure**, **Raised By**, **Operation condition** (and location if Port/At Anchor), **Occurrence type**, and a Description.
* The **Target date** can’t be earlier than the **Date issued**.
* When closing, a **Closure comment** is mandatory. Files are optional but recommended.

---

## 6) What “save” and “refresh” mean (in simple words)

* **Save** means the report or change is kept permanently and will still be there when you come back.
* After a save, the list **refreshes** so you can immediately see the new or updated row.
* Closing a defect moves it from **Active** to **Resolved** right away.

---

## 7) Sidebar items (for context)

* **Defect Log**: the Active/Resolved pages above.
* **Reports**: dashboards like Open Defects, Closure performance, Root Cause analysis, etc.
* (You’ve also added **CoC** and **Recurring Defects** in the sidebar; their behavior will be defined later.)

---

That’s the whole flow: **log it → track it → add notes/links → close it with a comment and evidence → find it later in Resolved**.
