ISSUE INVESTIGATION – COMPONENT DELETION / DEACTIVATION VALIDATION NOT WORKING

Context:
For the selected component (as shown in the screenshot), when attempting to deactivate or delete the component, the system is allowing the component to be deactivated directly.

However, the component currently has:
• Linked Active Jobs
• Linked Active Spares

Expected Behaviour:
The system should restrict the deletion or deactivation of a component if it has any linked Active Jobs or Active Spares.

Problem:
The validation is not triggering, and the component is getting deactivated directly even though active dependencies exist.

Investigation Points:

1. Validation Logic Check
Verify whether the system is checking for linked Active Jobs and Active Spares before executing the component delete/deactivate function.

2. Backend API / Service Logic
Inspect the backend service handling component deletion or deactivation and confirm whether dependency validation exists before updating the component status.

3. Database Query Verification
Check whether the system is running validation queries such as:

- Active Jobs linked to the component
- Active Spares linked to the component

4. Active Status Filtering
Verify whether the validation query is properly filtering records where:
is_active = Yes

5. Missing Dependency Check
Confirm whether the component deletion function is directly updating:
is_active = No
without checking linked Jobs and Spares.

Root Cause Identification:
Determine whether the issue is caused by:
• Missing validation logic
• Incorrect dependency query
• Validation executed after update
• Incorrect component ID mapping
• Vessel filtering issue

Required Correction:

1. Before executing component deletion or deactivation, the system must validate:

- Active Jobs linked to the component
- Active Spares linked to the component

2. If any active records exist, the system must block the action.

3. Display an error message such as:

"Component cannot be deleted or deactivated because active Jobs or Spares are linked to it. Please deactivate or delete the linked Jobs and Spares first."

4. Only allow deletion or deactivation after all linked Jobs and Spares are inactive or removed.

Expected Result:

• Components with Active Jobs or Spares cannot be deleted or deactivated.
• Dependency validation is enforced before updating component status.
• Proper error message is displayed when restriction conditions are met.
