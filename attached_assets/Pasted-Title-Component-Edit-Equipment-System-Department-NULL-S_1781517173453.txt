Title: Component Edit – Equipment / System Department NULL Selection Error Analysis

Objective:
Analyze why an error occurs when editing a Component and selecting "NULL" in the Equipment / System Department field, even though "NULL" is available in the dropdown. Identify the root cause and implement a corrective solution.

Issue Description:
While editing an existing Component record, if the user selects "NULL" in the Equipment / System Department dropdown and saves the record, the system throws an error. Since "NULL" is provided as a valid dropdown option, the application should allow the selection and save the record successfully.

Analysis Required:

1. Verify the frontend dropdown configuration and determine how the "NULL" option is being sent to the API.
2. Check whether the frontend sends:

   * null
   * empty string ("")
   * string value ("NULL")
   * 0 or any default ID
3. Review backend validation rules for Equipment / System Department.
4. Verify whether the database column allows NULL values.
5. Check if foreign key constraints prevent saving NULL values.
6. Review update APIs, DTOs, Models, and Stored Procedures (if applicable) to identify where the validation fails.
7. Identify the exact layer causing the error and document the root cause.

Corrective Plan:

1. If NULL is intended to be a valid option:

   * Frontend should send a proper null value.
   * Backend should accept and process null values.
   * Database should allow NULL in the corresponding column.
   * Foreign key validations should be skipped when value is null.
2. Ensure create and edit screens behave consistently.
3. Add validation to prevent invalid values while allowing legitimate NULL selections.
4. Perform regression testing on:

   * Component Create
   * Component Edit
   * Bulk Import (if applicable)
   * Existing Components with Department assigned
   * Components with NULL Department

Expected Result:
Users should be able to select "NULL" from the Equipment / System Department dropdown and save the Component successfully without any validation or database errors, since NULL is presented as an available option in the UI.
