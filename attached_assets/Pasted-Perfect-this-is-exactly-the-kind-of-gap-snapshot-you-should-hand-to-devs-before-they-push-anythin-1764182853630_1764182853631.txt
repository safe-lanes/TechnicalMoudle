## 🚨 PHASE 1 – ABSOLUTE BLOCKERS (MUST FIX BEFORE ANYTHING ELSE)

These are **production killers**: if they’re not fixed, the PMS will behave wrong or fall apart.

### A. CRITICAL – Business Rule Violations

I’ll condense your 13 earlier items into 6 concrete epics devs must implement.

---

#### A1. Component Code Cascade & Delete (Rule #12 & #14)

**Related to:** E4, F1

**Tasks:**

1. **Implement safe updateComponent() backend logic**

   * On `component_code` change:

     * Update all references in a **single transaction**:

       * `Jobs` (if `component_code` stored alongside `component_id`)
       * `WorkOrders` Part A copy (display field)
       * Any `ComponentSpareLink` table where component_code is stored
     * All relations must still be keyed by `component_id`.
       → Code is just a label, ID is the truth.

2. **Implement Component Inactivation / Delete rules**

   * Prevent **hard delete** in production → use `status = INACTIVE`.
   * If parent has ACTIVE children:

     * Either **block** inactivation (preferred for now):

       > “Parent has active sub-components; deactivate children first.”
     * Or provide **explicit cascade option** (later).
   * When component is set to `INACTIVE`:

     * Set all its jobs to `INACTIVE` (no new WOs).
     * Leave existing WOs and history untouched.

---

#### A2. RH Correction + WO Re-trigger & Status (Rule #3, #6)

**Related to:** E2, E3

**Tasks:**

1. **RH Update Handler**

   * When parent RH is updated:

     * Compute delta and propagate to children (as per RH spec).
     * Re-evaluate **all RH-based jobs** on that component:

       * Recalculate `remaining_hours`.
       * If `remaining_hours <= 0` and no active WO → **create WO**.
       * If already has WO:

         * Only update status (DUE/OVERDUE) according to new RH.

2. **Status Recalculation (Grace → Overdue)**

   * On every RH update:

     * If job is beyond threshold:

       * Status becomes `OVERDUE` immediately.
       * Grace period only affects escalation alerts, not WO status.

3. **Restriction on backward corrections**

   * When office/admin correct RH backwards:

     * Do **not** allow new RH < last completed WO RH.
     * If violation → block with clear message.

---

#### A3. WO → Spare ROB Deduction + Location (Rule #9, #10)

**Related to:** E1, B1, B2

**Tasks:**

1. **Location-aware consumption logic**

   * For spares with multiple locations (A/B):

     * WO Part B must send `location` per spare line.
     * Backend must:

       * Validate location belongs to that spare.
       * Deduct ROB from that location only.
   * If more than 1 location exists and none selected → **reject save**.

2. **ROB never negative**

   * If `requested_qty > ROB`:

     * Deduct only `ROB` (down to 0).
     * Log `requested_qty`, `deducted_qty`, `shortage_qty`.
     * Raise anomaly flag for reconciliation.

3. **Warning for zero/blank consumed quantity**

   * If user enters `0` or leaves blank:

     * Show toast: “No quantity consumed; ROB remains unchanged.”
     * Still allow saving (some jobs may inspect only).

---

#### A4. Job Edit → Active WO Safety (Rule #15)

**Tasks:**

1. When job frequency is edited:

   * If there is an **active WO** for this job+component:

     * Do **not** change the due date of that WO.
     * Store `frequency_updated_at` for history.
   * For **next WO generation**:

     * Use new frequency.

2. If **no active WO**:

   * Recalculate next due based on new frequency immediately.
   * Generate WO if it is already due.

3. Backend must enforce this in job update endpoint.

---

#### A5. Modify PMS Revision Flow (Rule #17)

**Tasks:**

1. Add `version` column to:

   * `Components`
   * `Jobs`
   * `Spares` (if needed)
2. When a Modify PMS request is **approved**:

   * Increment version.
   * Save old snapshot in history table or in the Modify PMS record.
3. Allow “View Change History” per object.

---

#### A6. Approver Department Validation (Rule #19)

**Tasks:**

1. In WO approval endpoint:

   * Check WO’s `department`.
   * Check current user’s **HoD/approval roles** for that department.
   * If not authorized → reject:

     > “You are not authorized to approve WOs for this department.”
