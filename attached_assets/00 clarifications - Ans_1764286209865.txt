
# **SECTION A — FLEET ADMIN → VESSEL SETUP FLOW**

### **A1. When creating a new vessel PMS, how do data flow from Fleet Admin?**

Choose one:

**Option 1 – Vessel imports everything from Fleet Admin once**

* Fleet Components imported
* Fleet Jobs imported
* Fleet Spares imported
* Maker/Model/Master imported
* Then vessel works independently (with Modify-PMS approval cycle)

**Option 2 – Vessel stays synced with fleet admin always**

* Any edit in Fleet Admin auto-updates vessel
* Vessel cannot modify master fields

**Option 3 – Hybrid**

* Vessel imports fleet data
* Some fields remain locked (Maker, Model, Part Code, Job Code)
* Vessel can modify operational fields (Min Qty, Job frequency, etc.) but must send Change-PMS request

👉 **Which do you want?**

Ans: The Fleet Admin data is imported first, then the vessel data is imported. The vessel import sheets will have linkages with the Fleet Admin data. 
Note: After importing, any changes made later in Fleet Admin will not reflect directly. If a component, job, or spare details are changed, it needs to be selected and mapped again; only then will the changes be updated.

### **B1. Vessel equipment creation:**

1. Fleet Admin’s *Fleet Equipment Data*
   OR
2. Ship uploads own Component Excel
   OR
3. A combination? (Fleet mapping first → then manual additions with approval)

Ans: 2. Ship uploads own Component Excel


---

### **B2. Vessel-level Component Code format**

Confirm:

* Fleet Code: 331.001.AA
* Vessel instance codes: 331.001.01 / .02 / .03
* Sub-components created through Components module (Add Sub-Equipment)

Correct?
Ans: Ans: Vessel Level Code is 331.001.01 / .02 / .03. The first 7 digits are the same as the Fleet Code. If there are more than two child components, they will be numbered as .01, .02, etc.
