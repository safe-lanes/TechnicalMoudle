System Prompt Template - Maritime-focused, context-aware:

typescript
const SYSTEM_PROMPT = `You are an AI assistant for a Planned Maintenance System (PMS) used on maritime vessels.

CONTEXT:
- Current Vessel: {vesselName} (ID: {vesselId})

YOUR CAPABILITIES:
- Query work orders (overdue, due, completed) with filters
- Check spare parts inventory and low stock items
- View component details and running hours
- Generate maintenance status summaries and reports
- Create deep links to filtered dashboard views
- Provide maintenance prioritization recommendations

TONE & STYLE:
- Concise and action-oriented (crew are busy)
- Use maritime terminology (Main Engine, Chief Engineer, ROB, running hours)
- Highlight critical/urgent items clearly
- Always offer follow-up actions or navigation options
- Format lists and tables for easy scanning

TOOL USAGE GUIDELINES:
- ALWAYS call getworkordercounts first for summary questions
- Use generatedeeplink when user asks to "show me" or "take me to"
- Combine multiple tool calls for complex queries (e.g., overdue WOs + low stock spares)
- After listing items, offer to show details or navigate

RESPONSE FORMAT:
- Use markdown for formatting
- Use tables for multiple items
- Highlight **critical** and **urgent** items
- Always end with: "Would you like me to..." suggestions
`;
Define 11 Core Tools (OpenAI function calling format):

getworkorders - Get work orders with filters (vesselId, status?, componentCode?, dateRange?, limit?)

getworkorderdetail - Get single work order details (workOrderId)

getoverdueworkorders - Get overdue work orders (vesselId)

getdueworkorders - Get due work orders (vesselId, dateRange?)

getworkordercounts - Get work order status counts (vesselId)

getlowstockspares - Get low stock spares (vesselId)

getcriticalspares - Get critical spares (vesselId)

getcomponents - Get components list (vesselId, critical?, search?)

getrunninghours - Get running hours for component (componentId)

getjobs - Get jobs/maintenance templates (vesselId, componentId?)

generatedeeplink - Generate deep link to filtered view (page, filters)

Implement executeTool() Function:

Map tool names to storage layer queries

Use existing storage methods from server/storage.ts or server/services/*

Handle errors gracefully (return empty results with explanatory message)

Implement processChatMessage() Function:

Initialize OpenAI client with process.env.AI_INTEGRATIONS_OPENAI_API_KEY

Build messages array with system prompt + conversation history

Call OpenAI with gpt-4o model and tools array

Handle tool calls recursively (execute tools, add results, get final response)

Return formatted response with tool usage metadata

Error Handling:

Wrap OpenAI calls in try-catch

Return fallback message if AI service fails

Log errors for debugging

Step 1.3: Create Chatbot Router - server/routes/chatbot.ts
Requirements:

POST /technical/api/chat endpoint:

Use requireAuth() middleware

Accept request body:

typescript
{
  message: string;
  conversationHistory?: Array<{role: 'user' | 'assistant', content: string}>;
  context?: {vesselId: string; vesselName: string; currentPage: string};
}
Extract user role from req.session.user.role

Call processChatMessage() from chatbotService

Return response:

typescript
{
  response: string;
  toolsUsed?: string[];
  conversationHistory: Array<{role: 'user' | 'assistant', content: string}>;
}
Error handling: Return 500 with error message if service fails

Step 1.4: Mount Chatbot Router - Edit server/routes.ts
Add:

typescript
import chatbotRouter from './routes/chatbot';

// After other router mounts
app.use(chatbotRouter);
