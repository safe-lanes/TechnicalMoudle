I need you to implement an unsaved changes warning in the Bulk Update Running Hours modal on the /pms/running-hrs page. Currently, if a user opens the Bulk Update RH modal, enters running hours values for one or more components, and then closes the modal without saving — all their entered data is silently discarded with no warning. This is a data-loss risk, especially during monthly RH update sessions where an engineer may accidentally close the modal.

Understanding the Current Modal Structure:

The Bulk Update RH modal has the following elements that can dismiss/close it:

The "×" (close) button in the top-right corner of the modal

The "Cancel" button at the bottom-left of the modal footer

Potentially clicking on the dark backdrop/overlay outside the modal area (if that is currently enabled as a dismiss trigger — check the code)

All three of these dismiss paths must be intercepted by the unsaved changes warning when applicable.

What Counts as "Unsaved Changes" — Define Dirty State:

A change is considered "unsaved" (i.e., the modal is "dirty") if any one or more of the following conditions is true at the time the user attempts to close the modal:

Any component row's "Present Running Hours" input field has a value entered in it (i.e., the field is not empty / not blank)

Any component row's "Meter Replaced" checkbox has been ticked

The Comments field at the top has any text typed into it (not empty)

The Date Updated field has been manually changed from its default auto-filled value (today's date)

If none of these conditions are true — meaning the user opened the modal but did not touch anything — then closing via × or Cancel should work immediately and silently, exactly as it does today. No warning should appear in this case.

The Warning Behavior — What Should Happen:

When the user attempts to close the modal (via ×, Cancel, or backdrop click) and the modal is dirty (has unsaved changes), do the following:

Do NOT close the modal immediately. Intercept the close action.

Display a confirmation dialog — this should be a small, centered overlay that appears on top of the Bulk Update modal itself (not replacing it). It should be a simple, clean dialog box with:

A warning icon (e.g., a triangle with exclamation mark ⚠) at the top

A title that reads: "Unsaved Changes"

A message that reads: "You have unsaved running hour entries. If you close now, all entered values will be lost. Do you want to discard your changes?"

Two buttons:

"Discard Changes" — styled as a red or danger-colored button. Clicking this closes the confirmation dialog AND closes the Bulk Update modal, discarding all entered values.

"Keep Editing" — styled as a neutral/secondary button (outline or gray). Clicking this closes the confirmation dialog only and returns the user back to the Bulk Update modal with all their entered values intact exactly as they left them.

The confirmation dialog should be modal itself — meaning the user cannot interact with anything behind it until they make a choice.

The Escape key behavior: if the user presses Escape while the Bulk Update modal is open and the modal is dirty, treat it the same as clicking × — show the confirmation dialog. If the modal is clean (no unsaved entries), pressing Escape should close the modal immediately.

If the user presses Escape while the confirmation dialog is showing, treat it as clicking "Keep Editing" — dismiss the confirmation dialog and return to the Bulk Update modal.

"Discard Changes" Behavior — Full Reset:

When the user confirms they want to discard changes (clicks "Discard Changes"):

Close the confirmation dialog

Close the Bulk Update RH modal

Reset all state — clear all entered values, uncheck all Meter Replaced checkboxes, reset the Mode back to "Set Total" (the default), reset the Date Updated back to today's date, and clear the Comments field

This ensures that the next time the user opens the Bulk Update modal, it opens in a completely fresh state with no leftover values from the previous session

"Keep Editing" Behavior — Full Preservation:

When the user clicks "Keep Editing":

Close only the confirmation dialog

Return focus to the Bulk Update RH modal

All previously entered values must be fully preserved — every input field value, every Meter Replaced checkbox state, the Comments text, the Date Updated value, and the current Mode (Set Total or Add Delta) must be exactly as the user left them

The cursor/focus should ideally return to the last field the user was interacting with, or at minimum to the modal itself

Styling the Confirmation Dialog:

It should appear as a smaller dialog box centered within or over the Bulk Update modal — not a full-screen overlay

Use the same design language as the rest of the app — same font, same border radius, same box shadow style as other modals

The background behind the confirmation dialog (the Bulk Update modal) should become slightly dimmed or blurred to draw focus to the confirmation dialog

The "Discard Changes" button should use a red or danger color to signal the destructive nature of the action

The "Keep Editing" button should use a neutral style (outlined, gray, or secondary) to signal the safe/default action — keep editing is the safe choice

Make "Keep Editing" the visually prominent default (rightmost, or given slightly more visual weight) since accidentally discarding data is worse than accidentally staying in the modal

Backdrop Click Behavior:

Check whether the current Bulk Update modal closes when the user clicks on the dark backdrop/overlay outside the modal.

If yes, intercept that click as well and apply the same dirty-check logic — show the confirmation dialog if dirty, close immediately if clean.

If no (backdrop click is already disabled and does nothing), leave it as is — no change needed for that path.

Scope — What NOT to Change:

Do not apply this unsaved changes warning to the individual Update RH gear icon modal — only the Bulk Update RH modal needs this treatment (the individual modal is simpler and has fewer fields)

Do not change any other module, page, or route

Do not change any existing functionality of the Bulk Update modal — the Save button, Mode toggle, Date Updated field, Comments field, component rows, Meter Replaced checkbox behavior, and Status column must all continue to work exactly as before

Do not change the visual design or layout of the Bulk Update modal itself — only add the confirmation dialog as a new layer on top when needed

The "Showing 19 components" count label, the Utilization Rate column, and all other recent changes to the Running Hours page must remain unaffected

General Instructions:

This is a pure frontend change — no backend/API changes are needed

The dirty-state tracking must be implemented using component state (or equivalent reactive state management already used in this app) — track it from the moment the modal opens

Make sure the dirty state is also reset to "clean" immediately after a successful Save — so that if the user saves successfully and the modal closes, the next time they open it, no warning appears

Test mentally that all four dismiss paths (× button, Cancel button, backdrop click if applicable, Escape key) are covered for both dirty and clean states
