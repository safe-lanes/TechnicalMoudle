# Prompt: Fix “Manage IHM” placement & styling on Component form (do not shrink fields)

## What’s wrong (do not repeat)

* The **Component Category** input has been **shrunk** to make space for two IHM buttons.
* The **IHM status + Manage IHM** controls are placed **mid-row** and **break the layout/theme**.

## What I want

1. **Restore the full width** of all existing inputs in **Section A – Component Information** (Maker, Model, Serial No, Drawing No, Component Code, Component Category, Location, Critical, Installation Date, Commissioned Date, Rating, Condition Based, No of Units, Dept, Parent, Dimensions/Size, Notes).
   *Do not* reduce any column widths or squeeze controls into these grid cells.

2. **Move the IHM controls to a new, dedicated row placed directly below “No of Units”.**

   * Label (left): **IHM**
   * Status pill (next to label): **Unknown** / **Compliant** / **Attention** (colors per theme)
   * **Manage IHM** button (right aligned)

3. **Theme-correct styling**

   * Status pill (compact, rounded):

     * Unknown: neutral/gray (`bg-gray-100 text-gray-700`)
     * Compliant: green (`bg-green-100 text-green-700`)
     * Attention: red/orange (`bg-red-100 text-red-700` or the app’s existing danger color)
   * Button: use the app’s **secondary** button style (same radius, hover/focus, font size as other secondary buttons). No custom colors.

4. **No layout regressions**

   * Keep Section A grid exactly as before (same columns, gutters, spacing).
   * The new IHM row **spans the full form width** of Section A and **does not** reduce any field width above/below.
   * On small screens, the IHM row stacks naturally; the button stays right-aligned within the row.

---

## Where to change

Find the Component form section “A. Component Information”. You’ll see the IHM controls injected near **Component Category**. **Remove them from that cell** and render them in a new row right after the “No of Units” field row.
