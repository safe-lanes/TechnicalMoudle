TASK: ANALYSIS & FIX – DUPLICATE COMPONENT LINKAGES IN VESSEL COMPONENT MAPPING OVERVIEW

Objective:

Identify why **duplicate component linkages** are appearing in  
**Vessel Component Mapping Overview**, and implement a fix to ensure **only unique component code linkages** are shown.

--------------------------------------------------

1. Current Issue

• Same component code is appearing multiple times  
• Duplicate linkage entries visible for a single vessel  
• Violates requirement:

  → Each component code linkage must be UNIQUE per vessel  

--------------------------------------------------

2. Expected Behavior

• For a selected vessel:

  - Each component_code should appear ONLY ONCE  
  - No duplicate linkage rows  

--------------------------------------------------

3. Root Cause Analysis

--------------------------------------------------

A. Mapping Table Duplication

Check:

• spare_component_linkage / component_mapping table may contain:

  - Multiple entries for same:
    vessel_id + component_code  

Example:

V1 | C001  
V1 | C001  ❌ duplicate  

--------------------------------------------------

B. Join Multiplication Issue

• Query joining multiple tables:

  - fleet_component  
  - vessel_component  
  - mapping_table  

• If one-to-many joins exist → row multiplication  

--------------------------------------------------

C. Missing DISTINCT / GROUPING

• Query may not enforce uniqueness:

  - No DISTINCT  
  - No GROUP BY  

--------------------------------------------------

D. Incorrect Mapping Logic

• While inserting mapping:

  - System not checking existing linkage  
  - Allowing duplicate insert  

--------------------------------------------------

E. UI Rendering Raw Data

• UI displaying raw dataset without deduplication  

--------------------------------------------------

4. Corrective Plan

--------------------------------------------------

A. Backend Query Fix (MANDATORY)

Ensure uniqueness at query level:

Option 1:

SELECT DISTINCT  
  vessel_id,  
  component_code  

--------------------------------------------------

Option 2 (Preferred):

GROUP BY  
  vessel_id, component_code  

--------------------------------------------------

B. Fix Join Logic

• Ensure joins do NOT multiply rows  

• Use proper join keys:

  - fleet_equipment_code  
  - component_code  

--------------------------------------------------

C. Data Cleanup (CRITICAL)

Run one-time cleanup:

• Identify duplicates:

  GROUP BY vessel_id, component_code  
  HAVING COUNT(*) > 1  

• Remove extra records  

--------------------------------------------------

D. Enforce DB Constraint

Add unique constraint:

UNIQUE (vessel_id, component_code)

→ Prevent future duplicates  

--------------------------------------------------

E. Insert Logic Fix

Before inserting mapping:

• Check:

  IF EXISTS (vessel_id + component_code)  
  → Do NOT insert  

--------------------------------------------------

F. UI Safeguard (Optional)

• Deduplicate before rendering  

--------------------------------------------------

5. Validation

Test Cases:

• Single component mapped → appears once  
• Multiple mappings → no duplicates  
• After refresh → still unique  
• Bulk mapping → no duplicate creation  

--------------------------------------------------

Expected Result:

• Vessel Component Mapping Overview shows only unique component linkages  
• No duplicate rows for same component code  
• Data integrity maintained at DB level  
• Future duplicate insertion prevented
