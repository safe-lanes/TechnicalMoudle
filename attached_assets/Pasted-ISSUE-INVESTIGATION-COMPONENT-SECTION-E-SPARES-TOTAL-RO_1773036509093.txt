ISSUE INVESTIGATION – COMPONENT SECTION → E. SPARES → TOTAL ROB SHOWING WRONG

Context:
In the Component section under "E. Spares" (Highlighted Area), the "Total ROB" value displayed is incorrect.

When verifying the individual spare locations and their ROB values, the total shown in the UI does not match the expected sum of the available locations.

Problem Statement:
The Total ROB displayed in the Component → E. Spares section is incorrect.

Areas to Investigate:

1. Data Source Validation
   - Identify the table from which ROB values are being fetched.
   - Verify whether the values are coming from:
     • Spares master table
     • Spare stock table
     • Spare transaction table
     • Historical stock records.

2. Calculation Logic
   - Verify how Total ROB is calculated.
   - Check if the system is summing:
     Location A ROB + Location B ROB
   - Confirm that no additional hidden or historical locations are included in the calculation.

3. Duplicate or Historical Data
   - Check whether historical spare transactions or old locations are being included in the total calculation.
   - Verify if duplicate records exist in the stock table.

4. Backend Query Review
   - Inspect the SQL/API query used to calculate Total ROB.
   - Check for:
     • Incorrect joins
     • Aggregation errors
     • Inclusion of inactive locations.

5. UI Display Logic
   - Confirm whether the UI is recalculating totals independently or displaying the value returned from the backend.

Expected Behaviour:
Total ROB should be calculated strictly as:

Total ROB = Sum of ROB from all active spare locations defined in the Spares master (e.g., Location A + Location B).

Historical or inactive locations must not be included.

Corrective Plan:

1. Identify the exact backend query calculating Total ROB.
2. Remove any joins or aggregations that include historical or inactive location data.
3. Restrict calculation only to active spare locations defined in the Spares master.
4. Ensure UI displays the backend-calculated value without recalculating incorrectly.
5. Validate the corrected calculation using sample spare records.

Deliverables:
- Root cause of incorrect Total ROB calculation
- Corrected backend logic/query
- Verified UI display of accurate Total ROB.
