1. Admin Dashboard (Home Screen)
This is the landing page for the Fleet Admin. It provides a high-level summary and quick access to all modules.

UI Components:

Persistent Left-Hand Navigation: As seen in your screenshots, with links to: Dashboard, Fleet, Vessel, Maker, Component, Jobs, Spares, and a new one we'll call "Master Lists".

Main Content Area (Widgets):

Database Statistics: "Total Fleet Components" (Count from Fleet_Components table), "Total Master Jobs" (Count from Fleet_Jobs), "Total Makers" (Count from Makers).

Fleet Status: "Total Vessels Managed," "Vessels with Critical Overdue Jobs."

Data Integrity: "Components Missing Makers," "Jobs Not Linked to Components," "Spares Not Linked to Components." These are actionable links.

Backend Logic: This page is a "read-only" view. It runs several COUNT() queries on your database tables to populate the widgets.

2. Core Data Modules (The Libraries)
This is the heart of your database management. The workflow must enforce logical dependencies: Makers must exist before Components, and Components must exist before Jobs or Spares.

2.1. Maker Management
Database Table: Makers

Main Screen UI:

Search bar (by Maker Name or Maker Code).

"Add New Maker" button.

A searchable, sortable data grid with columns: Maker Code, Maker Name, Address, Action Buttons (Edit, Delete).

"Add New Maker" / "Edit Maker" Screen (Modal/Popup):

UI: A simple form with fields: Maker Name (Text, Required), Address (Text Area), Contact Person, Email, Phone.

Data Processing: On Save, the backend:

Validates the data (e.g., Maker Name is not null).

Generates the unique Maker Code (e.g., MKR-000001).

Creates/Updates the record in the Makers table.

API (Conceptual): POST /api/fleet/makers, PUT /api/fleet/makers/{maker_id}

2.2. Fleet Component Management (The "SFI Tree")
This is the most complex and important module. It must manage both the SFI hierarchy and your specific equipment models.

Database Tables: SFI_Tree (your ComponentTree), Fleet_Components (your Fleet_Component Sheet).

Main Screen UI: A two-panel layout.

Left Panel (SFI Tree): A tree-view (like Windows Explorer) loaded from your SFI_Tree table. This is for navigation.

Right Panel (Component List): A data grid showing the Fleet Components linked to the SFI group selected on the left.

Workflow Example:

Admin clicks "651 MOTOR AGGREGATES..." in the left tree.

The right panel updates to show all "Auxiliary Engine" models you have in your library (e.g., "CAT C4.4," "Yanmar 6EY18").

UI Options:

"Manage SFI Tree" button (for editing the tree itself).

"Add New Fleet Component" button.

"Add New Fleet Component" Screen (Modal/Popup):

UI: A multi-tab form.

Tab 1: General Details:

Fleet Equipment Name: (Text, e.g., "Auxiliary Diesel Engine").

SFI Group: (Tree-select, populated from SFI_Tree). This links the component to its SFI group.

Maker: (Searchable Dropdown, Required). This is a Foreign Key lookup to the Makers table (Makers.MakerCode).

Model: (Text, Required, e.g., "C4.4 ACERT").

Critical: (Yes/No Toggle).

Rating, Notes, etc.

Tab 2: Linked Jobs: A table showing all Fleet_Jobs associated with this component. Has "Add/Remove" buttons.

Tab 3: Linked Spares: A table showing all Fleet_Spares associated with this component. Has "Add/Remove" buttons.

Data Processing: On Save, the backend:

Generates the unique Fleet Equipment Code (e.g., 651.001.AA) based on your business logic (SFI + Maker/Model).

Saves the new record to the Fleet_Components table, linking the MakerCode.

API (Conceptual): POST /api/fleet/components, GET /api/fleet/components?sfi_group=651

2.3. Fleet Jobs Management
Database Tables: Fleet_Jobs, Join_Components_Jobs (a join table for the many-to-many relationship).

Main Screen UI:

Search/filter bar (by Job Title, Job Code, Component).

"Add New Master Job" button.

A data grid with columns: WO Code, Job Title, Maintenance Basis, Interval, Assigned To.

"Add New Master Job" Screen (Modal/Popup):

UI: A form with all fields from your Fleet_Jobs Excel doc (WO Title, Maintenance Basis dropdown, Interval Value, Interval Unit dropdown, Assigned To dropdown, Brief Work Description text area).

Crucial UI Feature: "Link to Components"

A button that opens a popup window.

This window shows the Fleet_Component tree.

The admin checks all components this job applies to (e.g., "Clean L.O. Filter" can be linked to 5 different engine models).

Data Processing: On Save, the backend:

Generates the unique WO Code (e.g., JOB-00001).

Saves the job details to the Fleet_Jobs table.

Saves the links (e.g., FleetComponentID and FleetJobID) into the Join_Components_Jobs table.

API (Conceptual): POST /api/fleet/jobs, POST /api/fleet/jobs/{job_id}/link_component

2.4. Fleet Spares Management
Database Tables: Fleet_Spares, Join_Components_Spares.

Logic: Identical to "Fleet Jobs Management." An admin creates a master spare part (e.g., "Fuel Filter Element"), links it to a Maker, and then links it to all compatible Fleet_Components.

2.5. Master Lists Management (Your Lists Sheet)
Purpose: To manage all the dropdown options in your application without hard-coding them.

UI: A simple admin screen.

A dropdown to select the list to edit: "Department," "Rank," "Interval Unit," "Component Category," "Location," etc.

A simple grid below to "Add," "Edit," or "Delete" values for the selected list (e.g., add a new rank "Trainee Engineer").

Data Processing: Simple CRUD operations on your Lists table.

3. Data Import / Export (The "Excel Tool")
This is the "power user" feature for building the database initially. It belongs as a sub-section of the Admin Dashboard.

UI: A simple screen with two sections:

Download Templates: Buttons to download the blank, pre-formatted Excel templates you defined (Fleet_Component, Fleet_Jobs, etc.).

Upload Data: An "Upload File" area.

Data Processing (Backend): This is the most complex part.

Admin uploads Fleet_Component.xlsx.

The backend parses the file row by row.

It validates the data: Does the Maker Name in the file exist in the Makers table? If not, reject the row and provide an error report.

It finds the MakerCode from the Makers table.

It generates the Fleet Equipment Code.

It inserts the new, validated record into the Fleet_Components table.

Crucially, the uploads must be done in the correct order: Makers first, then Components, then Jobs and Spares. The UI should enforce this.
