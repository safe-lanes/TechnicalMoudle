Got it — the “Close” action updates the defect in the database, but the **Resolved** tab stays empty or looks like it has “no data”. That almost always means the **UI state/filtering/pagination** isn’t aligned with the new status, or the API query being used for the Resolved list isn’t returning what the UI thinks it should.

Below is a **complete, practical fix plan** you can hand to Replit. It’s written in simple steps, with example code they can adapt (React + React Query on the front-end, Node/Express + SQL/ORM on the back-end). If you’re using other stacks, the same logic applies.

---

## 1) Root-cause checklist (what typically breaks)

Ask Replit to check these first:

1. **Status mismatch / casing**
   UI filters for `"closed"` but DB stores `"Closed"` (or `"Resolved"`). Use a single, canonical enum.

2. **Wrong filter on Resolved tab**
   Query uses `status = 'Closed'` but you mark rows as `'Resolved'`, or vice-versa. For safety, include both.

3. **Stale UI cache**
   After closing, the UI doesn’t invalidate/refetch the Resolved list, so it looks empty.

4. **Sticky filters/search**
   A previous search term, fleet, vessel, date, or “Due/Overdu” filter is still applied and hides all rows.

5. **Pagination edge case**
   You switch tabs on page 3, but Resolved only has 1 page → blank grid. Always reset to page 1 on tab change.

6. **Toggle interactions**
   An “Include Closed Defects” toggle affects the Resolved tab or vice-versa. The Resolved tab should **not** depend on that toggle.

## 2) Backend — make filtering reliable

### 2.1 Canonical status enum

Use one status source of truth and **migrate** existing records to it.

```ts
// shared/defectStatus.ts
export const DEFECT_STATUS = {
  OPEN: 'Open',
  PENDING: 'Pending',
  CLOSED: 'Closed',
  RESOLVED: 'Resolved',
} as const;

export const ACTIVE_STATUSES = [DEFECT_STATUS.OPEN, DEFECT_STATUS.PENDING];
export const RESOLVED_STATUSES = [DEFECT_STATUS.CLOSED, DEFECT_STATUS.RESOLVED];
```

### 2.2 List endpoint with explicit status filter + pagination

```ts
// GET /api/defects
// query: statusScope=active|resolved, q (search), vesselId, fleetId, page, pageSize, sort, etc.
app.get('/api/defects', async (req, res) => {
  const { statusScope = 'active', q = '', page = 1, pageSize = 20 } = req.query;

  const statuses = statusScope === 'resolved'
    ? RESOLVED_STATUSES
    : ACTIVE_STATUSES;

  // Build WHERE with optional filters
  const where: any = { status: { $in: statuses }, deletedAt: null };

  if (q) {
    where.$or = [
      { description: { $ilike: `%${q}%` } },
      { actionRequested: { $ilike: `%${q}%` } },
      { category: { $ilike: `%${q}%` } },
    ];
  }

  const offset = (Number(page) - 1) * Number(pageSize);

  const [rows, total] = await Promise.all([
    db.defects.findMany({
      where,
      orderBy: { updatedAt: 'desc' },
      skip: offset,
      take: Number(pageSize),
    }),
    db.defects.count({ where }),
  ]);

  res.json({ rows, total, page: Number(page), pageSize: Number(pageSize) });
});
```

### 2.3 Close endpoint sets consistent fields

```ts
// POST /api/defects/:id/close
app.post('/api/defects/:id/close', async (req, res) => {
  const { comment, attachments = [] } = req.body;
  const id = req.params.id;
  const userId = req.user.id;

  const updated = await db.defects.update({
    where: { id },
    data: {
      status: DEFECT_STATUS.CLOSED,          // canonical
      dateCompleted: new Date(),
      closedById: userId,
      closureComment: comment || null,
      // store attachments in a separate table or jsonb column
    },
  });

  res.json(updated);
});
```

## 3) Front-end — tabs, filters, and cache invalidation

### 3.1 Query keys include the status scope

```ts
// useDefects.ts
import { useQuery, useQueryClient, useMutation } from '@tanstack/react-query';
import { ACTIVE_STATUSES, RESOLVED_STATUSES } from '@/shared/defectStatus';

export function useDefects(params: {
  statusScope: 'active' | 'resolved';
  q?: string;
  page?: number;
  pageSize?: number;
}) {
  return useQuery({
    queryKey: ['defects', params.statusScope, params.q || '', params.page || 1, params.pageSize || 20],
    queryFn: async () => {
      const query = new URLSearchParams({
        statusScope: params.statusScope,
        q: params.q || '',
        page: String(params.page || 1),
        pageSize: String(params.pageSize || 20),
      });
      const res = await fetch(`/api/defects?${query.toString()}`);
      if (!res.ok) throw new Error('Failed to load defects');
      return res.json(); // { rows, total, page, pageSize }
    },
    keepPreviousData: true,
  });
}
```

### 3.2 Tabs reset pagination + clear sticky filters

```tsx
// DefectLog.tsx (simplified)
const [tab, setTab] = useState<'active'|'resolved'>('active');
const [page, setPage] = useState(1);
const [search, setSearch] = useState('');

function onTabChange(next: 'active'|'resolved') {
  setTab(next);
  setPage(1);          // avoid blank page from page overflow
  setSearch('');       // optional: clear search to avoid empty results
  // also clear other sticky filters here if needed
}
```

### 3.3 Closing a defect should refresh both lists

```ts
export function useCloseDefect() {
  const qc = useQueryClient();

  return useMutation({
    mutationFn: async ({ id, comment, attachments }: { id: string; comment?: string; attachments?: any[] }) => {
      const res = await fetch(`/api/defects/${id}/close`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ comment, attachments }),
      });
      if (!res.ok) throw new Error('Failed to close defect');
      return res.json();
    },
    onSuccess: () => {
      // Invalidate both lists so the row disappears from Active and appears in Resolved
      qc.invalidateQueries({ queryKey: ['defects', 'active'] });
      qc.invalidateQueries({ queryKey: ['defects', 'resolved'] });
    },
  });
}
```

### 3.4 The Resolved tab must **not** depend on “Include Closed” toggle

Make sure that toggle only affects the **Active** list (if you keep it at all). The Resolved tab should always call `statusScope=resolved`.

## 4) UI polish & guardrails

* **Empty state**: When a list is truly empty, show “No resolved defects yet” instead of a blank white area.
* **Counters**: Compute counts from `total` returned by each query; don’t sum arrays in the client across tabs.
* **Loading states**: Show a spinner/skeleton while fetching; don’t show “no data” during loading.
* **Status chips**: Ensure the “Open/Closed” badges reflect the canonical enum (avoid typos).
* **Consistency**: The Close modal should require a comment and allow attachments, but validation happens **client + server**.

1. **Seed data**: 3 open defects, 1 closed defect.
2. Open **Active** tab → expect 3 rows; **Resolved** tab → expect 1 row.
3. In **Active**, close one defect with a comment & attachment.
4. On success:

   * Row disappears from Active without page refresh.
   * **Resolved** tab now shows 2 rows.
   * Badge counts update (Active: 2, Resolved: 2).
5. Try on page 2 of Active → close the last item so Active now has only 1 page → verify no blank page error.
6. Apply a search filter, then switch to Resolved → ensure search is cleared (or intentionally preserved if that’s your rule) and rows render.
7. Hard refresh the browser → both tabs still correct (proves persistence).

Add console logs on the API and in the client (query key + params) to quickly spot any statusScope or page bugs.
