Raplit Analysis Prompt — Apply Edit Changes to All Fleet Jobs with Same Job Code
Module

PMS → Admin → Fleet Data → Fleet Job Management → Edit Job Details

🎯 Objective

When editing a Fleet Job from the Edit Job Details page, if multiple records exist in the fleet_jobs table with the same Job Code, then:

Any changes saved must be applied to ALL records having that same job_code.

This prompt requires:

Detailed technical analysis

Root-level behavior validation

A structured implementation plan

No immediate coding

📌 Business Rule Requirement

If:

job_code = X


exists in multiple rows inside fleet_jobs table,

Then:

Editing one of those records must update:

ALL rows WHERE job_code = X

🔍 Required Analysis
1️⃣ Current Data Model Analysis

Analyse:

Is job_code unique?

Or is it repeated per fleet equipment?

What is the primary key of fleet_jobs?

Is job_code treated as:

Business identifier?

Or just a display field?

Clarify whether:

Each Fleet Equipment has its own row with same job_code

Or job_code is already unique

2️⃣ Current Edit Flow Analysis

Inspect:

What column is used in UPDATE query?

Is it updating by:

id (primary key)?

job_code?

Is edit currently scoped to one record only?

3️⃣ Risk & Data Integrity Analysis

If updating all rows with same job_code:

Will equipment-specific fields be overwritten?

Are there vessel-specific overrides?

Are any fields that must NOT be bulk-updated?

Identify:

Which fields are global (job-level fields)

Which fields are equipment-specific

🧠 Architectural Consideration

Two possible scenarios:

Scenario A — job_code is Logical Master Identifier

If:

job_code represents a global Fleet Job template

Multiple records represent mappings to different fleet equipment

Then:

Correct update logic should be:

UPDATE fleet_jobs
SET wo_title = :wo_title,
    task_type = :task_type,
    ...
WHERE job_code = :job_code;

Scenario B — Data Design Issue

If:

fleet_jobs is mixing master + mapping data

job_code should belong to master table

equipment-specific data stored separately

Then:

A redesign may be recommended:

fleet_job_master

fleet_job_mapping

But this prompt should only analyse feasibility — not redesign unless necessary.

⚙️ Required Technical Plan
Step 1 — Identify Updatable Columns

Classify fields:

Global Fields (update across all job_code records):

wo_title

task_type

maintenance_basis

interval_value

unit

brief_work_description

department

criticality

job_priority

class_related

assigned_to

approver

is_active

Confirm final list during analysis.

Step 2 — Modify Update Query Logic

Instead of:

WHERE id = :id


Use:

WHERE job_code = :job_code


Only if confirmed safe.

Step 3 — Add Safety Layer

Before updating:

Count how many records share job_code

Log affected row count

Confirm update impact

Optional enhancement:

Show confirmation:
"This will update X records with same Job Code. Continue?"

(Analyse feasibility only — do not implement yet.)

Step 4 — Transaction Safety

Wrap update in DB transaction.

If failure:

Rollback

Return error

Step 5 — Frontend Handling

After save:

Return affected rows count

Refresh job list

Reflect updates consistently

🚨 Edge Case Analysis

Check for:

Case sensitivity in job_code

Leading/trailing spaces

Null job_code values

Duplicate unintended job codes

Partial update risks
