Office PMS Manual vs Current System

A source-traceable comparison of the supplied Office manual with the application as currently implemented.

24 September 2026 · Scope: Dashboard, Components, Work Orders, Running Hours, Spares, Stores, Reports, Modify PMS, and Admin/Bulk Data Import.

Executive summary. The manual broadly describes the same modules as the current system. The most consequential differences are the manual’s implication that all component changes need approval despite a direct-save path, an incorrect Running Hours inheritance rule, a missing Spares “create location” action in the documented workflow, a Stores Location export that calls the Inventory exporter, and an overbroad claim that every report offers both PDF and Excel. Several smaller wording/behavior differences are listed below. This is a documentation-and-source audit, not an end-to-end role/permission test or a claim that every screenshot is current.

The prose and representative embedded screenshots (including Figures 9, 35, 60, 66, 83, 103, and 105) were inspected. Findings requiring action

01 · Component save versus change-request approval High · product/policy review

Manual
Figures 35 and 37 tell users to click Save, then Submit to add or update a component. The Modify PMS introduction before Figure 90 says any component, job, spare, or store change must be submitted as a formal approved change request before it takes effect.
System
The current Component Register form has a direct Save path; an authorized component edit sends a PATCH /technical/api/components/:id without waiting for a Modify PMS request. Adding a component sends a direct POST. Modify PMS has a separate request-and-approval workflow. See client/src/components/ComponentRegisterAddEdit.tsx:845-862,937-969,1275-1282; client/src/pages/pms/Components.tsx:4201-4217,4437-4468.
Impact
Users could believe Save is a draft awaiting Submit/approval when it is actually a direct master-data change. The manual’s universal approval claim cannot safely be treated as enforced policy.
Action
Decide which edits, if any, must be approval-gated. Either enforce that policy in product permissions/workflow or amend Figures 35/37 and the Modify PMS introduction to distinguish direct authorized saves from formal change requests. Do not simply rename the button.

02 · Running Hours cascade direction is reversed High · manual correction

Manual
Note after Figure 66: “For components with an Inherited RH type, updates are cascaded to all child components.”
System
The service accepts a manual master update only when the selected source component has rhCounterType === 'MASTER'; it then updates the master and its inherited dependents. See server/modules/running-hours/services/runningHoursService.ts:905-922,980-1021.
Impact
The reversed instruction can lead users to choose the wrong counter and misunderstand which machinery readings will change.
Action
Replace the note with “Update the MASTER running-hours counter; the new reading cascades to components that inherit from that master.” Verify terminology with operations before publication.

03 · No create-location action in the documented Spares location editor Medium · product gap

Manual
Figure 76 says users can click + Create New Location from the spare’s Location dialog and then Save.
System
The location editor opens existing selections and validates names against allVesselLocations. On an unknown name it tells users to “create a new location first,” but this editor does not present the documented create action. See client/src/pages/spares/SparesNew.tsx:321-343,360-382.
Impact
Following the manual cannot complete a new-location stock update from that dialog. A separate admin/location workflow may exist, but it is not the in-context action Figure 76 promises.
Action
Either add a permission-aware, persisted create-location action there, or document the real route for creating a location before returning to the spare.

04 · Stores Location export produces Inventory output Medium · product gap

Manual
Stores “How To Export Store Items” (after Figure 86) directs users to follow Spares’ export steps; Spares Figure 83 explicitly says users may export Inventory, Location, or History information.
System
The Stores Export button calls exportHistoryToExcel only on History; both Inventory and Location call exportInventoryToExcel. See client/src/pages/stores/Stores.tsx:2603-2613.
Impact
A user on the Location tab receives the wrong dataset/shape for a location-specific audit.
Action
Provide a dedicated location export using the currently filtered location rows, or clearly relabel the action if a location export is intentionally unavailable.

05 · “PDF or Excel for all reports” is too broad Medium · report contract

Manual
Reports introduction and Figures 87–88 state that standard/compliance reports are available in PDF or Excel and instruct users to pick either format.
System
The Maintenance report Excel handler lists a defined set of supported IDs and tells users other Excel exports are “coming soon.” For Work Order Overview (wo-overview), requesting PDF deliberately downloads Excel because the wide matrix is not supported as a PDF. See client/src/pages/reports/MaintenanceReports.tsx:1170-1189,1301-1329.
Impact
Users may promise a PDF/Excel deliverable the application does not supply for a particular report.
Action
Document format availability by report (including Work Order Overview’s Excel-only behavior) or implement the missing formats. Do not generalize this gap to Spares reports: the three listed Spares IDs have explicit PDF and Excel handlers in client/src/pages/reports/SparesReports.tsx:473-562.

06 · “My Team” access note does not describe the current toggle Medium · role documentation

Manual
Figure 9 puts Me / My Team on the Operation dashboard; the note after Figure 11 says only Vessel Admin users can view and use the toggle.
System
The toggle is rendered on Operation when !isAdminScope, and may be disabled when no team scope is mapped; this is a scope/mapping condition, not a literal Vessel Admin-only display rule. See client/src/pages/pms/Dashboard.tsx:2790-2855. The preview’s Management tab was correctly selected by default, consistent with Figure 3.
Impact
Users may expect a switch they cannot use, or think a non-Vessel-Admin user seeing it is an access defect.
Action
Confirm the intended per-role team visibility policy, then update the Figure 11 note to describe it and explain the disabled state. Test Office/HOD/Vessel sessions before asserting exact role coverage.

07 · Export dialog changes on the Postponed tab Low · manual correction

Manual
Figures 59–60 show an Export All Work Orders Excel/PDF choice and a separate Export Component Jobs Excel choice.
System
On the Postponed tab the dialog instead labels the second choice Export Postponed Work Orders, exporting filtered postponed records and extra postponement fields. On other tabs the “All Work Orders” choice remains. See client/src/pages/pms/WorkOrders.tsx:1233-1287,1959-2008.
Impact
Readers on Postponed see a different result from the unqualified “all” instruction. Component Jobs export itself is present, not a missing feature.
Action
Add a short note or alternate screenshot for the Postponed export. Leave the current specialized export behavior intact unless policy says otherwise.

08 · Bulk Running Hours rules are omitted Medium · manual safety guidance

Manual
Figures 63–66 say to enter date, comments, values, and click Save, but do not explain restrictions on counter resets/decreases.
System
When vessel RH validation is enabled, Set Total to zero is blocked in bulk, a decrease without meter replacement is blocked, and Add Delta must be positive. The UI directs zero/reset cases to the individual update flow. See client/src/pages/pms/RunningHours.tsx:1383-1413.
Impact
A user preparing bulk entries may meet an unexpected block and cannot tell how to record a genuine meter replacement.
Action
Document the conditional validation and the approved individual reset/replacement route alongside Figures 63–66.

09 · Modify PMS approval is more than a single generic decision Low · workflow documentation

Manual
Figure 103 describes opening a Pending Approval request and approving or rejecting it in the dialog.
System
The current dialog can display Level 1 and Level 2 approval steps and tells the viewer which level is pending. Buttons depend on the active configured approver step, with a fallback for older requests/no approvers. See client/src/pages/pms/ModifyPMS.tsx:226-248,1198-1258 and server/modules/change-requests/services/changeRequestsService.ts:342-355.
Impact
A pending request may not yet be actionable for the viewer; one approval may not be final.
Action
Explain configured sequential approval levels and what “Awaiting Level … approval” means. Do not claim the attached manual specifies an “Office Head” approver: its Figure 103 text does not say that.

Recommended sequence

  1. Decide approval policy first. Component direct-save versus mandatory CR approval has operational and audit implications; align product behavior and manual before changing either.
  2. Correct safety-critical instructions. Fix MASTER → inherited RH direction and document bulk RH rejection/reset paths.
  3. Resolve demonstrable UI/export gaps. Choose an in-context Spares location creation path and make Stores Location export reflect location data.
  4. Update scoped documentation. List report formats by report, note Postponed export behavior, clarify team toggle availability and Modify PMS approval stages.

Verification still needed: role-by-role walkthrough (Office/HOD/Vessel), real file-download content checks, and representative data-state checks for approvals, RH updates, and imports. These are validation requests, not claims of failures. No application code or source manual was changed for this audit.
