## Usage and cost — how to check
- **Measured usage (per answer, per tenant, per model):** the service logs every answered question in
  `assistant_conversations` (`ts`, `tenant_domain`, `model`, `tokens_in`, `tokens_out`, `latency_ms`, `gate`). Monthly
  tokens per tenant and model, with the test tenants excluded:
  `select date_trunc('month', ts) as month, tenant_domain, model, count(*) as answers, sum(tokens_in) as tokens_in,
  sum(tokens_out) as tokens_out from assistant_conversations where tenant_domain <> 'smoke-suite-tenant' and
  tenant_domain not like 'deploy-iso-%' group by 1,2,3 order by 1,2,3;` on `sail-assistant-db`. Token counts are
  recorded by the luna build (the previous gpt-4o-mini build recorded none).
- **Actual spend:** the OpenAI usage/billing page, filtered to the OpenAI project and API key that
  `assistant-luna.env` uses — the assistant's usage and spend must be attributed with those project/key filters. The
  assistant's key differs from the SMS RAG container's key, but a separate API key does not by itself guarantee a
  separate bill (keys under one project share its invoice, and a key can be used by more than one service), so the
  filter, not the key's existence, is what separates the numbers. LlamaParse spend on the LlamaCloud usage page
  (parsing happens only at index-build time — none in serving).
- **Estimate only:** tokens × list price (READ from the model page: $0.20 / $1.20 per 1M in/out) ≈ $0.70 per 1,000
  answered questions at the measured 1,631 / 315 tokens. Not a billing figure.
